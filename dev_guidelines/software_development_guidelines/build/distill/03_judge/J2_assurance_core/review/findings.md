## F10, stated precisely

J2 says: SECURITY.4 (J3) carries a developer floor with 80% statement coverage and contradicts BEHAVIOUR.6 if judged as a target. Findings:
1. Wrong node. The floor is row L1126, position P4 of SECURITY.3 (Verification Techniques). SECURITY.4 (rows L1129, L1130, L1135) holds no coverage text.
2. As judged in J3, there is no contradiction in the decisions. J3 SECURITY.3 Decision lists no coverage target; its Rejected line says "A numeric structural-coverage target stated as a security requirement: not decided here, it belongs to the adequacy measure in ASSURANCE.BEHAVIOUR.6". J3 flags it (its F4): "consistency with the J2 verdict on adequacy needs checking".
3. The real defect is a circular deferral. J3 defers the 80% to BEHAVIOUR.6; BEHAVIOUR.6 defers it to J3 ("J3 must reconcile"). Neither unit's Positions or Rejected holds the position "a minimum of 80% statement coverage in a security-testing floor" (NIST, T1, row L1126, REG-1081, REG-1086, REG-1094). BEHAVIOUR.6 states "MUST NOT a coverage number gate a merge as a quality target", which that position would contradict if adopted.
4. Evidence on the merits: Google (fetched REG-048): "instead of treating 80% like a floor, engineers treat it like a ceiling"; and the coverage study (fetched REG-1565) finds low to moderate correlation once size is controlled. Both support BEHAVIOUR.6; neither bears on a security floor as such.
Left to the Opus pass: whether BEHAVIOUR.6 Rejected lists the L1126 80% (with its condition) so that J3's pointer lands on a decision.
