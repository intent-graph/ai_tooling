# Slot 13_srvsec: candidate sources for the five high-criticality server-side security gaps

## L1 headline

Authoritative sources exist for all five gaps (35 candidates, each opened), but only for randomness, timing-safe comparison, SQL injection and SSRF generally; for JavaScript-specific unsafe deserialization and for path containment the T1 candidates give facts and API warnings, not a recipe, and several are vendor or tool pages that will be admitted restricted. Certainty: grounded for existence, authorship and date of each row (fetched, through a summarising fetch tool, not raw text); inferred for tiers and gates; open for exact wording not quoted below.

Pinned:
- Candidates by proposed tier: T1: 25, T2: 9, T3: 1 (total 35; T4 never listed).
- Gaps left with no T1 candidate: none. Caveat: G-H4 (deserialization) and G-H5 (path containment) have no T1 that states the safe recipe; their T1 rows are advisories (facts), a changelog, an API warning (`path.isAbsolute`, `url.parse`, `fileURLToPath`) and a framework option (Express `root`). The Node `v8.deserialize` page (already admitted, SRC-202) showed no untrusted-data warning in the fetched digest: open.
- Failed fetches on T1 candidates: (1) NVD page for CVE-2017-5941 returned field names only (alternative used: the GitHub advisory, K28); (2) ASVS V5 and V15 first URLs, guessed from a wrong file number, returned 404 (retried with the real file names from the directory listing: ok); (3) Express `api.html#res.sendFile` and `/en/5x/api.html` returned only the index (retry on `/en/5x/api/response/`: ok); (4) Node `crypto.html` and its raw `.md` copy were truncated before `timingSafeEqual` twice (retry on the `#cryptotimingsafeequala-b` anchor: ok; the other crypto functions come from the truncated digest only); (5) undici `Dispatcher` docs returned no redirect details (undici is not a candidate; it is a note under "Set aside"). No T1 candidate is unfetched.

## L2 claims

Per gap (certainty in brackets):
- G-H1 Randomness and crypto misuse (grounded): T1 K01 (Node `crypto`: `randomBytes`, `randomInt`, `randomUUID`, `timingSafeEqual`, `scrypt`), K02 (MDN: `Math.random` not for security), K03 (MDN `getRandomValues`), K04 (MDN SubtleCrypto misuse warning), K06, K07 (OWASP cheat sheets, K06 lists `crypto.randomBytes`), K08 (ASVS 11.5.1 CSPRNG with 128 bits, 11.2.4 constant-time); T2 K05, K09, K10. Has a T1: yes. The `timingSafeEqual` text was read verbatim (grounded): wraps OpenSSL `CRYPTO_memcmp`, use instead of `===` for MAC or authentication tags, throws `TypeError` on different lengths.
- G-H2 Query injection (grounded): T1 restricted K11 (OWASP SQLi cheat sheet: parameterize, allowlist identifiers, escaping fragile; no JavaScript example), K12 (node-postgres: no parameters for identifiers), K13 (mysql2: `execute` is server-side prepared, `query` is client-side escaping), K14 (Prisma `$queryRaw` versus `$queryRawUnsafe`), K15 (MongoDB: BSON not strings, but `$where`, `mapReduce`, `$function` run JavaScript), K16 (Mongoose `sanitizeFilter`, `{ pwd: { $ne: null } }`), K08 (ASVS 1.2.4); T2 K17, K18. Has a T1: yes. No neutral T1 states NoSQL operator injection for Node; the nearest is vendor docs K15, K16 (facts only) and CWE-943 (K18, T2).
- G-H3 SSRF and outbound requests (grounded): T1 K19 (OWASP SSRF cheat sheet: allowlist, validate resolved IPs then connect only to validated addresses, disable redirects, IMDSv2), K21 (`net.BlockList`), K22 (`dns.lookup` uses `getaddrinfo` on the threadpool; resolve-then-connect gap), K23 (`url.parse` warning; use WHATWG `URL`), K24 (Fetch redirect modes `follow`, `error`, `manual`), K08 (ASVS 1.3.6 allowlist of protocols, domains, paths, ports); T2 K20, K25 (DNS rebinding origin paper). Has a T1: yes. Node-specific recipe (pinned connection via custom `lookup`) is not in any T1 read: inferred from K21, K22 plus K19; open.
- G-H4 JavaScript unsafe deserialization (grounded for facts, open for recipe): T1 K27 (js-yaml 4.0.0: `load` safe by default, `!!js/function` moved out), K28 (node-serialize CVE-2017-5941, IIFE code execution, no patched version), K29, K30 (structured clone: functions and DOM nodes throw `DataCloneError`, prototypes and accessors not preserved; algorithm text readable), K08 (ASVS 15.1.1); T2 K26 (CWE-502, no JavaScript example). Has a T1: yes (facts only). SRC-133 does not cover JavaScript, as slot 11 found.
- G-H5 Path containment in Node (grounded): T1 K31 (Express `sendFile` with `root` validates the resolved path within root; user input warning), K32 (node-tar CVE-2021-32804, repeated-root bypass), K34 (CVE-2026-58043, permission-model prefix over-grant), K23 (`fileURLToPath` decodes `%2e%2e`: do not rely on it alone), K08 (ASVS 5.3.2, 5.3.3 zip slip, 5.2.5 symlinks); T3 K33 (Zip Slip). Has a T1: yes. `fs.realpath`, `path.resolve` and the `fs.access` race caution sit in already admitted SRC-188 and SRC-127 (see unextracted sections below). A "resolve, realpath, prefix test" recipe has no T1 statement: inferred.

Unextracted sections of admitted pages (grounded: headings read, text not extracted):
- SRC-078 (Node security best practices; register row is admit-restricted, coverage slot 11 called it unrestricted for 06; the audit should confirm): headings "DNS Rebinding (CWE-346)", "HTTP Request Smuggling (CWE-444)", "Information Exposure through Timing Attacks (CWE-208)", "Exposure of Sensitive Information to an Unauthorized Actor (CWE-552)", "Uncontrolled Search Path Element (CWE-427)". It has no heading on SSRF or path traversal. The DNS rebinding section concerns the debugging inspector, not outbound requests: do not use it for G-H3. Authors listed: Rafael GSS, Ulises Gascon, Fraxken, Facutuesca, mhdawson and others.
- SRC-190 (Node HTTP): `insecureHTTPParser` warning "makes the server vulnerable to request smuggling" (digest, open); `headersTimeout`, `maxHeaderSize`.
- SRC-188 (fs) and SRC-127 (path): `fs.realpath*` family, `fs.access` race caution, `path.isAbsolute` "not safe for mitigating path traversals" (digest; `path.resolve`, `join`, `normalize` carry no traversal warning).
- SRC-202 (v8): serialize and deserialize sections read; no warning on untrusted input found (digest): open.
- SRC-066 (globals): its `fetch()` section (undici-powered, custom dispatcher) is not extracted; redirect semantics there are open.
- SRC-134 (OWASP JS and TS cheat sheet): not re-read here; open. SRC-135 (OWASP Node cheat sheet, grounded): its headings include "Set request size limits", "Perform output escaping", "Perform application activity logging", "Only return what is necessary", "Do not use dangerous functions"; it has no section on NoSQL injection, SSRF, path traversal, random numbers or timing: slot 11 gaps are confirmed there.
- SRC-132 (ASVS 5.0 tree): restricted to four requirements; K08 asks the audit to widen it to named requirements 1.2.4, 1.3.6, 5.2.3, 5.2.5, 5.3.2, 5.3.3, 11.2.4, 11.5.1, 15.1.1, 16.5.1.

Disagreements and tensions between candidates (grounded unless marked):
- ASVS 5.0 chapter V15 has no SSRF requirement (digest names 15.3.2 on external URL calls and redirects only), whereas V1 (1.3.6) and V5 (5.3.2) carry it: SSRF sits in three chapters (K08).
- K15 (MongoDB: "traditional SQL injection attacks are not a problem") against K16 (operator injection bypasses authentication): both true; the first speaks of string injection, the second of object injection. Record both.
- K11 treats ORMs as an option and warns that escaping is fragile; K13 recommends `execute` over `query`, which uses client-side escaping: consistent in direction, different in strength (inferred).
- K19 says disable redirects; K24 defines `manual` mode, but the undici note (digest) says a server-side client returns the actual redirect response, not an opaque one: the meaning of `redirect: "manual"` differs between browser and Node (inferred from digests; open).
- K10 and K01 agree; K05 says the Web Crypto draft makes no constant-time guarantee (digest).

Gaps (what I searched, and what remains):
- No T1 source states a Node-specific recipe for outbound request pinning (resolve once, connect to the validated address). Searched: Node docs (net, dns, http, globals), OWASP SSRF cheat sheet, OWASP community page, web search. Found only a contributor-written OWASP community page (set aside, see tally) and vendor blogs (dismissed).
- No T1 on password-hash parameters in Node beyond `scrypt` in K01 and OWASP numbers in K07 (language-neutral).
- No T1 for a path-containment recipe (`path.relative` check, `realpath`): open; extraction from SRC-127, SRC-188, K31 may only support parts of it.
- Request smuggling and uncontrolled search path: only SRC-078 headings, K34 (CVE-2026-58044 text, restricted facts) and the SRC-190 warning; no mitigation source read beyond them.
- NoSQL injection testing (OWASP WSTG) page was reached but the digest was generic: set aside, not re-fetched.
