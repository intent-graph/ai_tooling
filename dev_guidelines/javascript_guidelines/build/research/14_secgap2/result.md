## L2 claims

Clusters:
- Token and JWT verification (T-a): verify against a caller-fixed algorithm allowlist, never the token's alg; reject alg none; bind keys to the issuer; validate iss, aud, exp and type; do not mix HMAC and public-key algorithms; library facts for jsonwebtoken (9.0.0, decode does not verify) and jose (algorithms optional, defaults to all for the key). Consensus on the core, single-source on library facts; C11 and C14 inferred. C01 to C17.

- Header and CRLF injection (T-c): CR, LF, NUL in field values are invalid; Node setHeader throws ERR_INVALID_CHAR, validateHeaderName and validateHeaderValue exist since v14.3.0; Node treats CRLF in writeEarlyHints as application misuse; undici host-header advisory. Consensus for the Node check, single-source elsewhere. C23 to C29.
- Server-side template injection (T-d): never build templates from untrusted input; Handlebars and EJS facts and advisories; Kettle's defences as a T3 position. Open: no T1 for other engines. C30 to C39.
- File upload (T-e): extension allowlist and untrusted Content-Type, server-generated names, storage outside the web root, explicit limits (busboy and multer default to Infinity), no global multer, decompression-size checks. Consensus on the core; JavaScript signature check open. C40 to C48.
- Typosquatting screening (T-f): 61 percent of 174 malicious packages used typosquatting; npm blocks typosquats and recommends scopes; ASVS requires repository provenance; two T3 methods as evidence; no T1 screening procedure (open). C49 to C54.
- CSRF as a code-level duty (T-g): token or Fetch Metadata check for cookie-authenticated state changes, no unsafe methods for state change, constant-time token comparison, preflight-based API defence, SameSite as depth, csurf archived. Consensus on the core; OWASP and MDN both list a Fetch Metadata check among the primary defences (C69); token requirements (C92). C55 to C62, C69, C92.
- Clickjacking (T-g): frame-ancestors on every response, not in a meta element; frame-busting scripts ineffective; DoubleClickjacking needs transaction authorization; X-Frame-Options facts. C63 to C68.
- URL validation (T-h): parse with the WHATWG URL API, compare parsed scheme, canonical host and effective port to an allowlist, reject userinfo, no prefix matching, prefer server-side id mapping; parser-compatibility is inferred; specific differentials open. C70 to C75.
- Path containment (T-i): a raw string-prefix check passes a sibling directory (hapi inert CVE-2026-48049); path.isAbsolute is not a traversal check; path.resolve lets an absolute input replace the base; path.normalize is lexical; Node leaves path validation to the application; recipe open. - v8.deserialize (T-j): code and header facts only; no source says safe or unsafe (open). C83 to C85.
- Node fetch redirects (T-k): fetch is based on undici; httpRedirectFetch limit of 20 and cross-origin header removal; three undici advisories on header stripping; RedirectHandler options; MDN redirect values; manual mode returns the real response in undici (C91). C86 to C91.
