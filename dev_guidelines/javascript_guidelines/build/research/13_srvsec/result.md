- Randomness and crypto (G-H1): the Node crypto page is truncated in every fetch (HTML, .md, latest, v20, v26). timingSafeEqual wording comes from the v6 and v12 documentation (digests disagree on the added version, v6.3.0 versus v6.6.0, so neither is recorded; the error class is only 'throw an error' in those digests). - Query injection (G-H2): no admitted T1 on Sequelize, Knex or TypeORM raw queries; mysql2 page says nothing on query() versus execute() safety; the register has no source for ORM identifier handling beyond Prisma and pg.
- SSRF (G-H3): no T1 states the pinned-connection recipe for Node (C33 inferred); SRC-066 gives no fetch redirect semantics (C37 open); undici documentation is not in the register; SRC-078's DNS rebinding section covers only the inspector, so outbound rebinding rests on OWASP (C32).
- Deserialization (G-H4): no T1 gives a JavaScript safe-deserialization recipe; JSON.parse plus schema validation is covered by slot 02 and RUNSEC-C43; v8.deserialize has no warning to extract (C44).
- Path containment (G-H5): the resolve, realpath, prefix-test recipe is stated by no admitted source (C55); fs.realpath and the current fs.access text were unreadable.
- Brief wording check: SRC-078's information exposure section concerns npm publishing (C62), not response data; response-data exposure rests on ASVS 16.5.1 (C60).
