# Research result: 08 QUALITY (static checks, tests, CI gates)

## L1 headline

Authoritative guidance for QUALITY is strong on tool behaviour (ESLint, typescript-eslint, Prettier, Biome, node:test, Vitest, npm ci, GitHub required checks, OpenSSF Badge) and thin on normative practice: formatting, test strategy, coverage targets, mutation and property-based testing rest on single T2 or restricted sources, mostly Java and Google, so most "do X" rules here are `single-source` or `inferred`; certainty: grounded for tool facts, inferred for transfer to JavaScript.

Pinned:
- Number of claims: 46; by agreement: 3 consensus, 1 majority, 2 contested, 40 single-source, 0 open-agreement.
- Contested topics: formatter choice and whether linters should format (QUALITY-C13); coverage as a quality target (QUALITY-C36).
- Register sources not read in full, and why: every HTML source was read through the fetch tool's digest with verbatim passages requested, not as raw page text (the tool returns a model-made digest; quotes are marked tool-extracted). Gaps beyond that: SRC-312 (Airbnb guide) not fetched, no claim uses it; SRC-168 (fast-check) only the introduction page was returned, no seed/path replay or default run count read; SRC-179 (StrykerJS) the introduction page returned only a navigation hub, definitions come from the docs root page (same site, different URL); SRC-182 (Vitest coverage) threshold configuration not on the page returned; SRC-169 (GitHub protected branches) "last week" check-selection rule not found in the digest; SRC-239 and SRC-244 (Google JS and TS guides) only sampled sections returned, not the whole guide; SRC-299 (Google mutation testing) abstract page only, full text not read (restriction already limits it to abstract level); SRC-161 (Scorecard) only seven checks read of all; SRC-163 (OpenSSF concise guide) read by digest, the cooldown origin is still missing; SRC-175 (Playwright) best-practices page only partly digested; SRC-296, SRC-297, SRC-300 PDFs were read in full-text extraction (pdftotext), in part by search for the decisive passages, not line by line.

## L2 claims

Clusters (agreement, certainty, ids):
- ESLint configuration and gate mechanics: flat config, `recommended`, exit codes, `--max-warnings 0`, unused-disable reports, cache. single-source (one T1 page each), grounded for facts, inferred for the CI practice. QUALITY-C01 to C03, C05 to C08.
- typescript-eslint: `recommended` drop-in, `strict` only with proficiency and not semver-stable, typed linting buys deeper rules at a build-time cost. single-source, grounded. QUALITY-C04, C09, C10.
- Formatting: a dedicated formatter, not core lint rules; ESLint formatting rules deprecated; Prettier prints only; disable conflicting rules; `--check` in CI. consensus on "not core lint rules" (T1 + T2), single-source for tool facts, grounded. QUALITY-C11 to C16.
- Lint suppression and Google positions: Google TS bans `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`; Google JS requires semicolons. single-source (T2, positions only). QUALITY-C17 to C19.
- Static analysis as policy: linter or safe mode, fix warnings, one static-analysis tool before release, tools not the only mechanism, negative tests. single-source T1 (OpenSSF). QUALITY-C20 to C23.
- Node test tooling facts: node:test stable since v20, coverage experimental; strict assertion mode; Vitest and Jest facts. single-source per tool, grounded. QUALITY-C24 to C28.
- Test structure and flakiness: public-API behaviour tests, DAMP, real over mocks, 80/15/5 mix, flaky rate 0.15%, top flaky causes async wait, concurrency, order dependency; wait on conditions, not delays. single-source (Google T3, Java T2) and one majority; inferred transfer to JavaScript. QUALITY-C29 to C35.
- Coverage: not a quality target, useful to find untested code; Vitest provider facts. contested position pair, grounded for the study. QUALITY-C36, C27.
- Mutation and property-based testing: mutation score meaning, incremental mutation at review; property-based concept, shrinking, generator control. consensus on definitions, single-source on practice. QUALITY-C37 to C41.
- CI and platform gates: `npm ci` in CI, required checks count skipped as passing, Scorecard checks and their limits. single-source T1 restricted, grounded. QUALITY-C42 to C44.
- Security lint boundary: eslint-plugin-security false positives; dependency cooldown position. single-source, boundary tags. QUALITY-C45, C46.

Contested topics:
- Formatter choice and linter-or-formatter: ESLint TSC recommends dedicated formatters (Prettier, dprint) or `@stylistic`; Biome's docs hold its formatter handles all formatting decisions. QUALITY-C13.
- Coverage as a quality target: Inozemtseva and Holmes say do not use it as a target; OpenSSF Badge suggests test suites cover most branches (numeric MUST thresholds sit on unregistered pages). QUALITY-C36.

Gaps (detail in L3): no T1 normative source for formatting, test strategy, coverage numbers, mutation and property-based effectiveness; no JavaScript-specific empirical study admitted; no snapshot or mocking policy source; no fuzzing documentation for JavaScript; Silver and Gold badge pages not in the register.

### Gaps

What a guideline needs here that no admitted source grounds, with what was searched (the register and the audit's gap list; web search was not used beyond the fetches of register URLs and the pages named below):
- Formatting: no normative source on whether to auto-format at all; only tool facts (SRC-162, SRC-176 to SRC-178) and one T2 position (SRC-298). A second independent T2 was not found; no new search was run beyond reading the register pages.
- Testing strategy (mix, size, behaviour over implementation): only Java T2 (SRC-296) and Google T3 (SRC-320, SRC-321). The JavaScript flaky-test study (ICSME 2022), SWEBOK v4 testing and ISO/IEC/IEEE 29119 are not in the register (see late candidates).
- Coverage numbers: the OpenSSF Silver (80% statement) and Gold (90% statement, 80% branch, each only if a FLOSS tool can measure it) criteria sit on pages 1 and 2 of the badge site, which are not register rows; I read both but cannot cite them. The tension with SRC-297 is recorded in QUALITY-C36 without them.
- Property-based testing: no peer-reviewed source on shrinking or effectiveness; no JavaScript authority beyond fast-check's own docs; seed and path replay not read.
- Mutation testing: SRC-299 read at abstract level only; no independent second study; StrykerJS configuration and runner support not read.
- Fuzzing for JavaScript: only the Scorecard check (QUALITY-C44); OSS-Fuzz or ClusterFuzzLite JavaScript documentation not in the register.
- Snapshot testing and mocking policy: only tool docs (node:test snapshot stable from v23.4.0 in SRC-172, not turned into a claim) and Google's real-over-mocks position (QUALITY-C30).
- Typed linting versus plain linting performance numbers: SRC-181 gives no measurements.
- Pre-commit and CI wiring (Husky, lint-staged): no source in the register; Prettier's pre-commit advice is in QUALITY-C16.
- Playwright's isolation and CI frequency advice was read but not claimed: the register restricts SRC-175 to Playwright's own behaviour.
