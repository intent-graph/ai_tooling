## L1 headline

Authoritative guidance for this area is solid on TypeScript strictness, `unknown` versus `any`, and validating untrusted data at boundaries (OWASP, TypeScript handbook, tsconfig reference, typescript-eslint; grounded), thin for JSDoc-checked JavaScript (tool facts only, no admitted advocate, lagging TypeScript 7.0), and weakest for "no types" (no admitted source argues for it; one restricted 2017 study); the type-layer choice is the maintainer's and is recorded as contested, not settled. Certainty: grounded for the claims marked so, but every web page was read through a summarizing fetch tool (passages marked tool-extracted), not as a full verbatim page.

## L2 claims

Clusters (agreement, certainty, ids):
- Types are compile-time only: annotations and assertions do not check data at runtime, and assertions and `!` are unchecked escape hatches. consensus, grounded. TYPES-C02, C19, C23
- Node runs TypeScript by stripping types without checking; erasable syntax only; separate `tsc --noEmit`; no TypeScript under node_modules. mostly single-source (C04 consensus), grounded. TYPES-C03, C04, C05, C06, C07
- Strictness: enable `strict` (default from TypeScript 6.0), noImplicitAny, strictNullChecks, unknown catch variables; noUncheckedIndexedAccess and exactOptionalPropertyTypes are opt-in decisions; upgrades may add errors. consensus for C08, C10, C11; grounded. TYPES-C08 to C14, C43
- `unknown` over `any`; lint `no-explicit-any` and `no-unsafe-assignment`; treat `JSON.parse` output as `unknown` and validate. consensus, grounded (C18 inferred). TYPES-C15, C16, C17, C18, C24
- Narrowing: discriminated unions with `never` exhaustiveness, avoid truthiness on primitives; whether predicate bodies are checked is open. single-source; C20 open. TYPES-C20, C21, C22
- Validate data at every trust boundary: allowlist, structure or schema, server side, syntax plus semantics, resource and regex limits, allowlisted binding. consensus (OWASP and ASVS), grounded. TYPES-C27 to C34
- Schema tools: facts only for Ajv (schemas are trusted code), Zod, Valibot, Standard Schema; no admitted source compares them. single-source, grounded. TYPES-C35, C36, C37, C38
- JSDoc-checked JavaScript: how to enable, weaker checking, silent no-op tags, TypeScript 7.0 removals. consensus for C39 and C42, grounded. TYPES-C39 to C42, C44
- Google positions (position only): no ts-ignore comments, no const enum, interfaces for object types. single-source, grounded. TYPES-C25, C26
- Context: Node LTS rule; native type syntax is Stage 1; measured detection of 15 percent of public bugs by 2017 checkers; langsec recognizer principle; JSON.parse precision and `__proto__`. single-source, grounded or inferred. TYPES-C45 to C50

Contested topics:
- Type-layer choice: TypeScript vs JSDoc-checked JavaScript vs none (TYPES-C01). Far weaker grounds for "none": no admitted holder argues for it and its only ground is TYPES-C47 (T2 restricted, 2017); JSDoc-checked has facts only, no admitted advocate.

Gaps:
- "No static types": no second T2 ground, no maintainer rationale.
- Comparing schema-validation approaches: nothing admitted compares tools.
- Unsoundness of user-defined type guards: still no source (TYPES-C20 open).
- JSON.parse clause of ECMA-262 not readable; `__proto__` detail lives on an MDN page outside the register.
