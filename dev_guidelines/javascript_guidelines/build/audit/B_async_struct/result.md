# Audit result: group B_async_struct (slots 03_async, 04_struct)

## L1 headline

Of 74 rows audited (71 discovery candidates plus 3 origin rows added by the audit), 31 were admitted, 40 admitted restricted and 3 rejected; ASYNC keeps an admitted T1 for all seven of its sub-topics, while STRUCT has admitted T1 grounds only for its mechanics (modules, cycles, side-effect imports, object privacy, state mechanics) and none for layering, paradigm choice, naming or state-structure design. Certainty: grounded for every verdict (each candidate fetched by this audit), with the ECMA-262 section text and two full papers left unread, as stated in L3.

Pinned:
- 03_async: admitted 20, restricted 17, rejected 0 (37 rows: 36 candidates plus origin row ASYNC-K09o).
- 04_struct: admitted 11, restricted 23, rejected 3 (37 rows: 35 candidates plus origin rows STRUCT-K25o and STRUCT-K35o).
- Sub-topics left without an admitted T1 source: 04_struct dependency direction as a layering principle (cycles themselves have T1); 04_struct paradigm choice; 04_struct naming; 04_struct state-structure design (state mechanics have T1); 04_struct function API design has T1 only in restricted form (STRUCT-K11 declaration-file scope, STRUCT-K15 lint rule). 03_async: none at sub-topic level; inside sub-topics, no source at all for the operational-vs-programmer error distinction or for concurrency limiting, retry and backoff.
- Candidates whose standing claim was found false: none. Factual misreadings found in discovery (not standing claims): ASYNC-K09 default mode `warn` (false, the default is `throw`), ASYNC-K31 "TC39 list shows stage 2.7" (false, it lists Stage 2), STRUCT-K13 "never extend built-ins" (misread: the warning is against monkey patching built-in prototypes), STRUCT-K02 cast as tolerating cycles (it advises usually avoiding them).

## L2 claims

Per slot:
- 03_async: admitted 20, restricted 17, rejected 0. Every sub-topic keeps an admitted T1 (promises K01 K20; unhandled rejections K02 K08 K09 K24; cancellation K05 K14 K13 K16 K21; timeouts K05 K03 K13 K18; error types and causes K06 K15 K22; event-loop blocking K02 K11; workers K04 K12 K17). Grounded.
- 03_async, K09 conflict resolved: the Node default for unhandled rejections is `throw`, grounded by K08 and by the origin row ASYNC-K09o (Node v15.0.0 release notes, PR 33021); the CLI page entry itself was not readable through the fetch tool. Grounded.
- 04_struct: admitted 11, restricted 23, rejected 3. Rejections: STRUCT-K31 (Sorhus "Pure ESM package", G3, opinion with no spec or runtime standing, rationale outdated by stable `require(esm)`), STRUCT-K34 (React) and STRUCT-K35 (Redux), both G4, replaced by their origin STRUCT-K35o (Codd 1970) and out of scope by maintainer decision Q3. Grounded.
- 04_struct, sub-topics without admitted T1: layering principle, paradigm choice, naming, state-structure design; function API design has only restricted T1. These rest on T2 sources that are not about JavaScript (Parnas, Cook, Hofmeister, Feitelson, Berger, Ray, Coblenz, Codd), all restricted to their scope. Grounded.
- 04_struct, the default-export disagreement survives audit intact: Google JS and TS guides (no default exports, reason stated in TS) against Airbnb 10.6 (prefer default), MDN neutral; all three guides admitted restricted to positions. Grounded.

Patterns in what failed or was restricted:
- The discovery fetch tool returns model summaries, and four discovery statements were summary artefacts or misreadings (K09 default, K31 stage, STRUCT-K13, STRUCT-K02); extraction must quote the page text. Grounded.
- Official but stale: a T1 body does not make every page current (ASYNC-K10 offloading, STRUCT-K14 `var` and IIFE examples, Google JS guide frozen, V8 2018 pages). Grounded.
- Scope transfer: studies of C#, Java, cross-language GitHub data and 1970s papers were proposed for JavaScript sub-topics; all admitted only for their own scope, transfer to JS marked as inference. Grounded.
- Framework docs used to fill a general gap (state design): rejected in favour of the origin they restate. Grounded.
- MDN guide pages (not reference pages) restate the specs and add editorial advice: restricted to mechanism facts, advice recorded as MDN's position. Inferred as a policy reading: the tier list names "MDN reference pages".
- Lint and tool documentation is T1 only for the tool's own behaviour (standing rule, G5); recalibrated webpack up to T1 restricted and eslint-plugin-import kept at T3 for its opinion. Grounded.

### 03_async: sub-topics without an admitted T1, and what stage 3 needs

All seven sub-topics keep an admitted T1. Remaining work for the extractor:
- Operational versus programmer errors: no admitted source states the distinction (ASYNC-K15 checked, it does not). Lead, not audited: the Joyent-era Node.js error-handling document by Dave Pacheco, the likely origin of the distinction; it must pass G1 and G2 before use. Open.
- Concurrency limiting, retry and backoff: no candidate in the slot. Leads, not audited: IETF RFC 9110 for `Retry-After` semantics (T1 for HTTP, boundary web architecture); a vendor engineering article on exponential backoff with jitter would be T3 only. Open.
- ECMA-262 section text (Promise objects, Await, HostPromiseRejectionTracker, Error cause): read it in a reader that does not truncate (the multipage pages truncate at the table of contents in the fetch tool). Open.
- ASYNC-K09 entry text: quote it verbatim; this audit could not reach it through the fetch tool. Open.
- ASYNC-K35 and ASYNC-K34: read the full papers (preprint for DrAsync; the OOPSLA PDF beyond page 1). Open.

### 04_struct: sub-topics without an admitted T1, and what stage 3 needs

- Dependency direction as a layering principle: T1 covers cycles only (STRUCT-K01, K07, restricted K02). The principle rests on one restricted T2 (STRUCT-K21) and so is `single-source`. A second independent T2 is needed; lead, not audited: Parnas 1979, "Designing Software for Ease of Extension and Contraction" (IEEE TSE), the origin of the "uses" hierarchy. Open.
- Paradigm choice: no T1 can exist for a choice; STRUCT-K25 and K25o are one dataset, K22 is conceptual. The guideline can at most state that no evidence favours a paradigm inside JavaScript, recorded as inferred. Open.
- Naming: two independent T2 (STRUCT-K23, K24) meet the claim threshold for general naming claims; JavaScript transfer stays inferred. The extractor should read the EMSE 2018 version of K23 and check the experiment language of K24. Inferred.
- State-structure design: mechanics have T1 (live bindings K03 K04, module cache K07, private fields K12); design rests on STRUCT-K35o (T2, restricted principle) and K26 (interviews). Immutability mechanics (Object.freeze, const) belong to slot 01 LANG. Open.
- Function API design: only restricted T1 (STRUCT-K11 declaration-file scope, K15 lint rule) plus T2 positions (K19, K18). A claim on parameter objects or optional arguments needs two independent T2 grounds: K19 (W3C TAG) and K18 (Google) are independent and may suffice, both recorded as positions. Inferred.
