# Audit result: group C_domsec_runsec (slots 05 DOMSEC, 06 RUNSEC)

All checks made 2026-10-12. Certainty marks: grounded = I fetched and checked it; inferred = follows
from what I fetched; open = not established. Reading method: every web page was read through the
fetch tool, which returns a model-written extract answering a question, not the raw page; I asked for
verbatim quotes on every point that decided a verdict. Six PDFs were read as raw text by local
extraction (DOMSEC-K28, K29, K30, K34; RUNSEC-K25, K34o; first pages, plus a text search in K30). Raw downloads with curl
were not available. ECMA-262 (RUNSEC-K11) could not be read past its table of contents by any copy I
tried.

## L1 headline

Of 76 audited rows (71 candidates plus 5 origins I added), 71 survive: 38 admitted outright, 33
admitted with a stated restriction; 5 are rejected. Every DOMSEC and RUNSEC sub-topic keeps an admitted T1
source except JavaScript-specific unsafe deserialization (grounded: the discoverer's search found none, and I confirmed that the only T1 candidate, OWASP's Deserialization sheet, has no JavaScript content).
Path injection and secrets in code are covered, but only by thin or language-neutral T1 sources.

Pinned:
- 05_domsec: admitted 20, restricted 15, rejected 1 (36 rows: 35 candidates plus 1 origin, DOMSEC-K12o).
- 06_runsec: admitted 18, restricted 18, rejected 4 (40 rows: 36 candidates plus 4 origins, RUNSEC-K21o, K22o, K34o, K35o).
- Sub-topics left without an admitted T1 source: 06_runsec, unsafe deserialization (JavaScript-specific). None in 05_domsec.
- Candidates whose standing claim I found false: none fully false. One is partly false: RUNSEC-K01 says its named contributors are Node.js Security Working Group members, but the working group's roster lists only three of the five (facutuesca is not listed, and mhdawson is a TSC emeritus). Factual errors outside the standing column are listed in L2.

Per slot:
- 05_domsec: admitted 20, restricted 15, rejected 1. Grounded.
  - The one rejection is K12, the WICG Sanitizer draft (G4). The draft says its content was merged into WHATWG HTML. I found that origin at HTML section 8.5.2 (setHTML, setHTMLUnsafe) and section 8.6, "HTML Sanitization", which includes security considerations on DOM clobbering, script gadgets and mutation XSS. It is added as K12o and admitted T1, which closes the discoverer's open gap "Sanitizer API normative text not located". Grounded.
  - No sub-topic is left without a T1. One detail remains open: no normative text on handling the `javascript:` scheme, because the URL Standard never mentions it (grounded). A lead for stage 3, which I did not check: the HTML Standard's javascript: URL navigation steps and MDN's javascript: scheme page. Open.
- 06_runsec: admitted 18, restricted 18, rejected 4. Grounded.
  - The four rejections are mirrors or derivatives replaced by their origins:
    - K21: OSV mirror; replaced by the GitHub advisory page, K21o.
    - K22: unreadable NVD mirror; replaced by the Node.js security-release post, K22o, cross-checked against the CVE record.
    - K34: OWASP community wiki; replaced by the 2009 OWASP Israel talk, K34o, admitted T3 for the mechanism only.
    - K35: Web Security Academy page with product promotion; replaced by Gareth Heyes's 2023 research post, K35o, admitted T3 restricted.
  - Unsafe deserialization (JavaScript-specific) has no admitted T1. Its only T1 grounds are language-neutral: K18, OWASP, covering PHP, Python, Java and .NET only; and K19, ASVS 15.1.5, which names deserialization as dangerous functionality. Grounded.
  - Thin T1 coverage:
    - Path injection: K36, one sentence of Node docs; K19, ASVS 5.3.2, language-neutral; K13, restricted.
    - Secrets in code: K16, language-neutral.
  - Grounded.

Errors I found in the discovery file (not standing claims, but they matter for extraction):
- RUNSEC-K22: the discoverer gives CVSS 9.1. The CNA record (hackerone) and the Red Hat ADP both give CVSS 7.1 High, vector AV:L. The 9.1 figure appears only in search snippets. Grounded.
- RUNSEC-K03: the Node threat model does not mention `vm`; only the V8 sandbox, `node:vfs` and the permission model are disclaimed. The `vm` disclaimer lives in K05. Grounded.
- RUNSEC-K35: the title is the whitepaper's, but the URL is the Academy page, which shows no author. Grounded.
- DOMSEC-K35: the name "Freddy Bräuning" is wrong; the Mozilla participant is Frederik Braun (mozfreddyb), the SRI editor. Grounded.
- DOMSEC-K24: the page tables 14 vulnerability classes, not 16. Grounded.
- DOMSEC L2, two false tensions:
  - The iframe page K27 has no `'*'` postMessage example.
  - K11 against K25 is no currency conflict: `setHTMLUnsafe` is Baseline 2025, while `setHTML` and the `Sanitizer` API have limited availability.
  - Grounded.

Patterns in what failed or was restricted:
- Mirrors and derivatives (OSV, NVD, a community wiki, a vendor training page) were proposed instead of their origins; each origin was easy to find. Grounded.
- OWASP cheat sheets carry no date or author on the page. Their git history fixes G2: all 14 sheets used here were last changed between 2026-10-03 and 2026-10-04, many in a burst of commits by the project leader. Grounded.
  - The Input Validation sheet's last commit says it was rewritten with AI assistance. I restricted RUNSEC-K15 under G1 for that reason. Grounded.
- Several T1 sources ground rules without reasons: ASVS requirements have no rationale text, and the OWASP Node.js sheet recommends third-party npm packages without vetting them. These are restricted under G3 and G2. Grounded.
- Research papers from before 2019 pass for mechanism, but their prevalence figures are dated. They are restricted to "figures stated with their year". Grounded.
- Vendor pages (PortSwigger) pass only for facts, never for advice, and only at T3. Grounded.
- Discoverer standing claims were mostly right but loose about names and rosters (RUNSEC-K01, DOMSEC-K35). Grounded.
