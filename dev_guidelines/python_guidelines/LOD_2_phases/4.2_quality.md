## Overview
<!-- Lines 20-37 -->

Quality tooling automates the enforcement of coding standards, catching issues before they reach code review or production. The goal is not perfection but consistency—a codebase where every file looks like it was written by the same careful developer.

The modern Python quality stack has consolidated around a few key tools. Ruff has emerged as the dominant linter, combining the functionality of flake8, isort, pyupgrade, and dozens of plugins in a single, blazingly fast tool. Black remains the standard formatter, though Ruff now offers compatible formatting. Type checkers (mypy, pyright) verify that types align with declarations.

These tools work in layers:
1. **Formatters** handle syntax: line length, quotes, whitespace
2. **Linters** catch logic: unused imports, undefined variables, anti-patterns
3. **Type checkers** verify semantics: function signatures, type compatibility

The key principle: **automate the mundane, debate the significant**. Formatting is not worth human discussion time—let Black decide. Code style rules should be in linter config, not review comments. Type errors should fail CI, not require manual verification.

## 4.2.1 Linting
<!-- Lines 40-83 -->

Linting analyzes code without executing it, catching bugs, enforcing style, and identifying anti-patterns. Ruff is the modern choice—it's 10-100x faster than alternatives and replaces multiple tools.

**Ruff Configuration:**
```toml
[tool.ruff]
line-length = 88
target-version = "py310"

[tool.ruff.lint]
select = [
    "E", "W",    # pycodestyle
    "F",         # Pyflakes
    "I",         # isort
    "B",         # flake8-bugbear
    "UP",        # pyupgrade
    "SIM",       # flake8-simplify
]
ignore = ["E501"]  # Line length handled by formatter

[tool.ruff.lint.isort]
known-first-party = ["mypackage"]
```

**Rule Selection Strategy:**
- Start with `select = ["E", "F"]` (errors only)
- Add rule sets incrementally after fixing existing violations
- `--fix` auto-fixes many issues
- Use `# noqa: CODE` sparingly, with explanation

**Common Rule Sets:**
| Code | Purpose |
|------|---------|
| `E/W` | PEP 8 style |
| `F` | Logic errors (undefined names, unused imports) |
| `I` | Import sorting |
| `B` | Bug-prone patterns |
| `UP` | Upgrade to modern syntax |

## 4.2.2 Formatting
<!-- Lines 86-130 -->

Formatters rewrite code to a canonical style, eliminating all formatting discussions. Black pioneered the "opinionated formatter" approach—minimal configuration, maximum consistency.

**The Black Philosophy:**
- One way to format: no choices, no debates
- Deterministic: same input always produces same output
- PEP 8 compliant with sensible line-length defaults

**Configuration:**
```toml
[tool.black]
line-length = 88
target-version = ["py310"]

# Or use Ruff's formatter (Black-compatible)
[tool.ruff.format]
quote-style = "double"
```

**What Formatters Handle:**
- Indentation and whitespace
- Quote style (Black uses double quotes)
- Line breaks and continuations
- Trailing commas
- Blank lines between definitions

**What Formatters Don't Handle:**
- Import sorting (use `ruff check --fix` or `isort`)
- Naming conventions (linter domain)
- Code structure (architectural decisions)

**Integration:**
```bash
# Format all Python files
ruff format .

# Check without modifying
ruff format --check .
```

## 4.2.3 Type Checking
<!-- Lines 133-180 -->

Type checkers verify that your type annotations are consistent and correct. They catch entire categories of bugs at development time rather than runtime.

**Tool Options:**
- **mypy**: Original, most widely used, strict ecosystem
- **pyright**: Microsoft, faster, better inference, VSCode integration

**Basic mypy Configuration:**
```toml
[tool.mypy]
python_version = "3.10"
strict = true
warn_return_any = true
warn_unused_ignores = true

[[tool.mypy.overrides]]
module = "tests.*"
disallow_untyped_defs = false
```

**Strictness Progression:**
1. Start permissive: `check_untyped_defs = true`
2. Add typing: `disallow_untyped_defs = true`
3. Full strict: `strict = true`

**Common Patterns:**
```python
# Explicit type narrowing
def process(value: str | None) -> str:
    if value is None:
        return "default"
    return value.upper()  # mypy knows value is str here

# Type ignore with reason
result = external_api()  # type: ignore[no-untyped-call]  # Legacy API
```

**Gradual Typing Strategy:**
- New code: Fully typed from the start
- Existing code: Add types during modifications
- Third-party: Use `types-*` stub packages or inline ignores

## 4.2.4 Pre-commit
<!-- Lines 183-225 -->

Pre-commit runs checks automatically before each commit, catching issues at the earliest possible point. It's the enforcement layer that makes quality tooling effective.

**Installation:**
```bash
pip install pre-commit
pre-commit install
```

**Configuration (.pre-commit-config.yaml):**
```yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.1.6
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format

  - repo: https://github.com/pre-commit/mirrors-mypy
    rev: v1.7.0
    hooks:
      - id: mypy
        additional_dependencies: [types-requests]
```

**Hook Ordering:**
1. Fast formatters first (Ruff format)
2. Linters with auto-fix (Ruff lint --fix)
3. Linters without auto-fix
4. Type checkers (slowest)

**Key Practices:**
- Run in CI to catch skipped hooks (`pre-commit run --all-files`)
- Pin hook versions for reproducibility
- Use `--no-verify` sparingly (emergencies only)
- Auto-update periodically: `pre-commit autoupdate`

## 4.2.5 CI Pipeline
<!-- Lines 228-279 -->

Continuous Integration runs quality checks on every push and pull request. It's the authoritative quality gate—code that fails CI doesn't merge.

**GitHub Actions Example:**
```yaml
name: CI
on: [push, pull_request]

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v1
      - run: uv sync --dev
      - run: uv run ruff check .
      - run: uv run ruff format --check .

  type-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v1
      - run: uv sync --dev
      - run: uv run mypy src

  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python: ["3.10", "3.11", "3.12"]
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v1
      - run: uv python install ${{ matrix.python }}
      - run: uv sync --dev
      - run: uv run pytest
```

**Pipeline Structure:**
1. **Lint job**: Fast, fails early on style issues
2. **Type check job**: Catches type errors
3. **Test job**: Runs test suite, often with matrix
4. **Build job**: Ensures package builds correctly

**Optimization:**
- Cache dependencies between runs
- Run jobs in parallel where independent
- Fail fast on first error in PR contexts
