## Overview
<!-- Lines 19-36 -->

The environment is the foundation of reproducible development. A properly configured environment ensures that code behaves identically across developer machines, CI systems, and production deployments. This phase establishes the development toolchain before any code is written.

Environment setup follows the principle of **isolation**—each project operates in its own sandbox, with explicit dependencies and tool versions. This prevents the "works on my machine" problem and enables deterministic builds.

**Key Decisions:**
- Python version selection (use latest stable unless constraints exist)
- Virtual environment strategy (always isolate)
- Package manager choice (pip, uv, poetry)
- IDE/editor configuration (team-consistent settings)

## 2.1.1 Python Installation
<!-- Lines 39-63 -->

Python version selection impacts available language features, library compatibility, and long-term maintenance. Use `pyenv` to manage multiple Python versions without modifying system Python.

**Version Selection Criteria:**
- Use the latest stable minor version (e.g., 3.12) for new projects
- Match production Python version exactly
- Consider library compatibility for scientific/ML projects

**System Python Warning:**
Never install packages into system Python. System Python is for the operating system—your projects need isolation.

```
System Python (/usr/bin/python3)
    └── Reserved for OS tools

pyenv Python (~/.pyenv/versions/3.12.x/)
    └── Your development base
        └── Virtual environments per project
```

## 2.1.2 Virtual Environments
<!-- Lines 66-100 -->

Virtual environments provide project isolation—each project gets its own set of installed packages, independent of other projects and system-wide installations. This is not optional; it is a fundamental requirement for reproducible development.

**Why Isolation Matters:**
- Project A needs `requests==2.28.0`
- Project B needs `requests==2.31.0`
- Without isolation, one project breaks

**Environment Types:**

| Tool | Use Case | Pros |
|------|----------|------|
| `venv` | Standard library | No extra dependencies |
| `virtualenv` | Legacy/advanced | Faster, more features |
| `conda` | Scientific computing | System-level packages |

**Best Practice:** Use `venv` for most projects. It's built into Python 3.3+ and sufficient for typical development.

```bash
# Create environment
python -m venv .venv

# Activate (Unix)
source .venv/bin/activate

# Activate (Windows)
.venv\Scripts\activate
```

## 2.1.3 Development Tools
<!-- Lines 103-132 -->

Modern Python development benefits from specialized tools that handle dependency resolution, package installation, and project management. Choose tools that balance speed, reliability, and team familiarity.

**Package Managers:**

| Tool | Speed | Lock Files | Use When |
|------|-------|------------|----------|
| `pip` | Moderate | `requirements.txt` | Simple projects |
| `uv` | Fast | `uv.lock` | Speed matters |
| `poetry` | Moderate | `poetry.lock` | Full project management |

**Recommended Stack:**
- **uv** for fast dependency installation (10-100x faster than pip)
- **pip** as fallback for compatibility
- Lock files for reproducibility

**Core Development Tools:**
```bash
# Essential tools (install globally with pipx)
pipx install ruff          # Linting + formatting
pipx install mypy          # Type checking
pipx install pre-commit    # Git hooks
```

## 2.1.4 IDE Configuration
<!-- Lines 135-171 -->

Consistent IDE configuration across a team reduces friction and catches errors early. Configure your editor to run formatters and type checkers automatically.

**VS Code (Recommended):**
```json
// .vscode/settings.json
{
    "python.defaultInterpreterPath": ".venv/bin/python",
    "[python]": {
        "editor.formatOnSave": true,
        "editor.defaultFormatter": "charliermarsh.ruff"
    },
    "python.analysis.typeCheckingMode": "basic"
}
```

**PyCharm:**
- Set project interpreter to `.venv/bin/python`
- Enable type checking (Preferences → Editor → Inspections)
- Configure code style to match team conventions

**Key Extensions/Plugins:**
- **Ruff**: Linting and formatting
- **Pylance/Pyright**: Type checking
- **Python Debugger**: Step-through debugging

**Team Configuration:**
Commit IDE settings to version control:
```
.vscode/
├── settings.json      # Project settings
├── extensions.json    # Recommended extensions
└── launch.json        # Debug configurations
```
