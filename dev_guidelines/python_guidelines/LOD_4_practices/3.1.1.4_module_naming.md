> Short, lowercase names that describe contents.

## Module Names
<!-- Lines 16-31 -->

```python
# Good module names
models.py       # Data structures
services.py     # Business logic
utils.py        # Only if truly generic utilities
exceptions.py   # Custom exceptions
config.py       # Configuration
constants.py    # Constants

# Avoid
misc.py         # Too vague
helpers.py      # Usually too vague
stuff.py        # Never
```

## Package Names
<!-- Lines 34-48 -->

```
# Good structure
mypackage/
├── __init__.py
├── core.py         # Core functionality
├── models.py       # Data models
├── api/            # API subpackage
│   ├── __init__.py
│   └── routes.py
└── utils/          # Utilities subpackage
    ├── __init__.py
    └── validators.py
```

## Import Considerations
<!-- Lines 51-58 -->

```python
# Name should read well in imports
from mypackage.models import User      # Good
from mypackage.data_models import User # Also good
from mypackage.m import User           # Too short
```
