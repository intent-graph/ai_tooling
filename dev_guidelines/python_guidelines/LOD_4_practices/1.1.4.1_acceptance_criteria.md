> Define when a feature is "done" with testable conditions.

## Format: Given-When-Then
<!-- Lines 17-23 -->

```gherkin
Given [context/precondition]
When [action is performed]
Then [expected outcome]
```

## Example: Task Creation
<!-- Lines 26-42 -->

```gherkin
Feature: Create Task

Scenario: Successful task creation
  Given I am logged in
  When I create a task with title "Buy milk"
  Then the task appears in my task list
  And the task has status "pending"

Scenario: Empty title rejected
  Given I am logged in
  When I create a task with empty title
  Then I see error "Title is required"
  And no task is created
```

## Criteria Checklist
<!-- Lines 45-51 -->

Each criterion must be:
- [ ] Testable (can verify pass/fail)
- [ ] Specific (no ambiguity)
- [ ] Independent (doesn't depend on other criteria)
- [ ] Agreed upon (stakeholder sign-off)

## Anti-Patterns
<!-- Lines 54-58 -->

- **Vague:** "System should be fast" (how fast?)
- **Untestable:** "User should be happy"
- **Implementation detail:** "Uses Redis for caching"
