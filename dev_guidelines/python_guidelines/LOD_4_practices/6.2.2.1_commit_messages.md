> Writing clear, useful commit messages.

## Conventional Commits Format
<!-- Lines 23-31 -->

```
<type>(<scope>): <subject>

<body>

<footer>
```

## Types
<!-- Lines 34-46 -->

| Type | Description |
|------|-------------|
| `feat` | New feature |
| `fix` | Bug fix |
| `docs` | Documentation only |
| `style` | Formatting (no code change) |
| `refactor` | Code change (no feature/fix) |
| `test` | Adding/changing tests |
| `chore` | Maintenance (deps, config) |
| `perf` | Performance improvement |
| `ci` | CI/CD changes |

## Examples
<!-- Lines 49-49 -->

### Simple (Subject Only)
<!-- Lines 52-59 -->

```bash
git commit -m "feat: add user registration endpoint"
git commit -m "fix: handle empty list in dashboard"
git commit -m "docs: update API reference"
git commit -m "refactor: extract validation logic"
```

### With Scope
<!-- Lines 62-68 -->

```bash
git commit -m "feat(auth): add OAuth2 support"
git commit -m "fix(api): handle rate limit errors"
git commit -m "test(user): add registration tests"
```

### With Body
<!-- Lines 71-81 -->

```bash
git commit -m "feat(auth): add OAuth2 support

Implements Google and GitHub OAuth providers.
Tokens are stored encrypted in the database.
Session timeout is configurable via AUTH_TIMEOUT.

Closes #123"
```

## Subject Line Rules
<!-- Lines 84-96 -->

```bash
# Good
"fix: prevent crash on empty input"   # Imperative mood
"feat: add dark mode toggle"          # Present tense
"docs: clarify installation steps"    # <= 50 chars

# Bad
"Fixed the bug"           # Past tense
"Fixes"                   # Too vague
"Added new feature for handling user authentication..."  # Too long
```

## Body Guidelines
<!-- Lines 99-110 -->

```bash
# Explain WHY, not WHAT (code shows what)
git commit -m "refactor: simplify user lookup

The previous implementation used three database queries.
This change consolidates them into a single JOIN query,
reducing latency by ~40% for the user profile page.

Measured with production-like data (10k users)."
```

## Footer Conventions
<!-- Lines 113-126 -->

```bash
# Reference issues
Closes #123
Fixes #456
Refs #789

# Breaking changes
BREAKING CHANGE: API now returns JSON instead of XML

# Co-authors
Co-authored-by: Name <email@example.com>
```

## Enforcing with commitlint
<!-- Lines 129-142 -->

```bash
# Install
npm install -g @commitlint/cli @commitlint/config-conventional

# commitlint.config.js
module.exports = {
  extends: ['@commitlint/config-conventional']
};

# .husky/commit-msg
npx --no -- commitlint --edit "$1"
```
