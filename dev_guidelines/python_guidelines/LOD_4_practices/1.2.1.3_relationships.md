> Define how entities connect: one-to-one, one-to-many, many-to-many.

## Relationship Types
<!-- Lines 17-23 -->

| Type | Example | Implementation |
|------|---------|----------------|
| One-to-One | User ↔ Profile | FK with unique constraint |
| One-to-Many | Project → Tasks | FK on the "many" side |
| Many-to-Many | Task ↔ Tags | Junction table |

## Python Representation
<!-- Lines 26-40 -->

```python
# One-to-Many
@dataclass
class Task:
    id: UUID
    project_id: UUID | None  # FK to Project

# Many-to-Many
@dataclass
class TaskTag:
    task_id: UUID
    tag_id: UUID
```

## Relationship Questions
<!-- Lines 43-49 -->

For each relationship:
- Required or optional?
- On delete: cascade, restrict, or nullify?
- Can it change after creation?
- Needs history/audit?

## Anti-Patterns
<!-- Lines 52-56 -->

- Storing IDs as comma-separated strings
- Circular dependencies without clear owner
- Missing cascade rules
