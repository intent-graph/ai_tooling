> Define what problem you're solving in one clear paragraph.

## Core Pattern
<!-- Lines 16-30 -->

**Template:**
```
[Users/System] currently [pain point]. They need [capability] so that [outcome].
The solution must [key constraint].
```

**Example:**
```
Marketing teams currently spend 4+ hours weekly manually compiling reports
from multiple data sources. They need automated report generation so that
they can focus on analysis rather than data gathering. The solution must
integrate with existing Salesforce and Google Analytics accounts.
```

## Key Elements
<!-- Lines 33-41 -->

| Element | Question | Example |
|---------|----------|---------|
| Who | Who has this problem? | Marketing teams |
| What | What's the pain? | Manual report compilation |
| Why | Why does it matter? | Wastes 4+ hours/week |
| Goal | What do they need? | Automated reports |
| Constraint | What limits the solution? | Must integrate with existing tools |

## Anti-Patterns
<!-- Lines 44-48 -->

- **Solution masquerading as problem:** "We need microservices" (that's a solution)
- **Too vague:** "Users need better reporting" (what's better?)
- **No measurable impact:** No indication of why this matters
