## Diátaxis Framework
<!-- Lines 18-49 -->

Diátaxis organizes documentation by user need.

**Four Documentation Types:**

| Type | Orientation | User State |
|------|-------------|------------|
| Tutorial | Learning | "I want to learn" |
| How-To | Tasks | "I want to do X" |
| Reference | Information | "I need to know Y" |
| Explanation | Understanding | "I want to understand Z" |

**Documentation Matrix:**
```
                PRACTICAL          THEORETICAL
              ──────────────────────────────────
STUDYING      │  Tutorials   │   Explanation   │
(learning)    │  (learning)  │  (understanding)│
              ├──────────────┼─────────────────┤
WORKING       │   How-To     │    Reference    │
(doing)       │   (goals)    │   (information) │
              ──────────────────────────────────
```

**Key Principle:**
Don't mix types. A tutorial shouldn't become a reference. A how-to shouldn't explain theory.

## Tutorials
<!-- Lines 52-120 -->

Tutorials are learning-oriented. They guide beginners through steps.

**Tutorial Characteristics:**
- Designed for learning, not accomplishing tasks
- Step-by-step progression
- Achievable by complete beginners
- Provides a sense of accomplishment

**Tutorial Structure:**
```markdown
# Getting Started with MyProject

By the end of this tutorial, you will have:
- Installed MyProject
- Created your first widget
- Deployed it locally

## Prerequisites
<!-- Lines 84-86 -->
- Python 3.11+
- 10 minutes of time

## Step 1: Installation
<!-- Lines 89-103 -->

Install MyProject using pip:

```bash
pip install myproject
```

Verify the installation:

```bash
myproject --version
```

You should see: `myproject 1.0.0`

## Step 2: Create a Widget
<!-- Lines 106-121 -->

Create a new file called `my_widget.py`:

```python
from myproject import Widget

widget = Widget(name="my-first-widget")
widget.configure(color="blue")
```

Run your widget:

```bash
python my_widget.py
```

## What's Next?
<!-- Lines 124-132 -->

Congratulations! You've created your first widget.

- Learn more in the [How-To Guides](../how-to/index.md)
- See all options in the [API Reference](../reference/api.md)
```

## How-To Guides
<!-- Lines 123-189 -->

How-to guides are task-oriented. They help users accomplish specific goals.

**How-To Characteristics:**
- Assumes basic knowledge
- Focuses on a specific task
- Provides working solution
- Addresses real-world scenarios

**How-To Structure:**
```markdown
# How to Handle Authentication Errors

This guide shows how to handle authentication failures gracefully.

## Problem
<!-- Lines 152-154 -->

When authentication fails, users see cryptic error messages.

## Solution
<!-- Lines 157-171 -->

Use the `AuthErrorHandler` to provide user-friendly messages:

```python
from myproject.auth import AuthErrorHandler

handler = AuthErrorHandler()

try:
    user = authenticate(credentials)
except AuthError as e:
    message = handler.get_user_message(e)
    display_error(message)
```

## Customizing Error Messages
<!-- Lines 174-185 -->

Override default messages in your configuration:

```python
handler = AuthErrorHandler(
    messages={
        "invalid_credentials": "Please check your email and password.",
        "account_locked": "Contact support to unlock your account.",
    }
)
```

## See Also
<!-- Lines 188-201 -->

- [Authentication Setup](./authentication-setup.md)
- [Error Handling Reference](../reference/errors.md)
```

## Reference and Explanation
<!-- Lines 192-249 -->

Complete the documentation with reference and explanation.

**Reference Documentation:**
- Complete, accurate information
- Organized for lookup (not learning)
- Generated from code when possible

```markdown
# Configuration Reference

## Environment Variables
<!-- Lines 217-232 -->

| Variable | Type | Default | Description |
|----------|------|---------|-------------|
| `DEBUG` | bool | `false` | Enable debug mode |
| `DATABASE_URL` | str | Required | Database connection string |
| `LOG_LEVEL` | str | `INFO` | Logging verbosity |
```

**Explanation Documentation:**
- Provides background and context
- Explains design decisions
- Discusses alternatives and tradeoffs

```markdown
# Understanding the Plugin Architecture

## Why Plugins?
<!-- Lines 235-238 -->

MyProject uses a plugin architecture to allow customization
without modifying core code.

## How Plugins Work
<!-- Lines 241-247 -->

Plugins are discovered at startup using Python entry points:

1. Plugin registers in `pyproject.toml`
2. MyProject scans for entry points
3. Plugins are loaded and initialized

## Design Tradeoffs
<!-- Lines 250-255 -->

We chose entry points over explicit imports because:
- No code changes needed to add plugins
- Plugins can be distributed separately
- Clear separation of concerns

## Alternatives Considered
<!-- Lines 258-261 -->

- Import hooks: Too magical, hard to debug
- Configuration files: Less discoverable
```
