## Core Concept
<!-- Lines 31-56 -->

**Definition:** Technical debt is the implied cost of future rework caused by choosing an expedient solution now instead of a better approach that would take longer.

**Key Properties:**
- Like financial debt, it accrues interest over time
- Some debt is strategic (deliberate trade-off)
- Untracked debt is the most dangerous kind
- Debt compounds—shortcuts make future shortcuts more likely

**The Debt Quadrant (Martin Fowler):**

|              | Deliberate | Inadvertent |
|--------------|------------|-------------|
| **Prudent**  | "Ship now, refactor later" | "Now we understand" |
| **Reckless** | "No time for design" | "What's coupling?" |

**When Debt is Acceptable:**
- Time-to-market pressure with a repayment plan
- Prototype/proof-of-concept code
- Learning through implementation

### Strangler Fig Pattern
<!-- Lines 227-244 -->

Replace debt incrementally:

```python
# Old code (debt)
def get_user_legacy(user_id):
    # Complex, untested, fragile
    ...

# New code (clean)
def get_user(user_id: str) -> User:
    # Use new implementation, fall back to legacy
    try:
        return new_user_service.get(user_id)
    except NotMigrated:
        return get_user_legacy(user_id)
```
