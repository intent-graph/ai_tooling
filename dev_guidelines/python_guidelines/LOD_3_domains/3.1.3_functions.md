## Function Design
<!-- Lines 16-52 -->

Functions are the fundamental unit of behavior. Design them to be small, focused, and testable.

**Design Principles:**
- **Single responsibility**: One reason to change
- **Explicit inputs**: Dependencies as parameters
- **Clear outputs**: Prefer returns over mutation
- **Reasonable size**: Fits on one screen

**Size Guidelines:**
- Ideal: 5-15 lines
- Maximum: ~50 lines
- If longer: Consider splitting

**Abstraction Level:**
Functions should operate at consistent abstraction levels:

```python
# BAD: Mixed abstraction levels
def process_order(order):
    validate(order)
    for item in order.items:           # Low-level
        item.price = item.price * 0.9  # Detail
    save_to_db(order)

# GOOD: Consistent abstraction
def process_order(order):
    validate(order)
    apply_discount(order)
    save(order)
```

## Parameters
<!-- Lines 55-113 -->

Parameter design determines function usability and flexibility.

**Parameter Order:**
1. Required positional parameters
2. Optional positional parameters
3. `*args` (if needed)
4. Keyword-only parameters
5. `**kwargs` (if needed)

```python
def fetch_users(
    organization_id: int,           # Required positional
    limit: int = 100,               # Optional positional
    *,                              # Keyword-only after this
    include_inactive: bool = False,
    sort_by: str = "created_at",
) -> list[User]:
    ...
```

**Positional-Only (`/`):**
```python
def pow(x, y, /):  # x and y must be positional
    return x ** y

pow(2, 3)      # OK
pow(x=2, y=3)  # Error
```

**Keyword-Only (`*`):**
```python
def connect(host: str, *, port: int = 5432):
    ...

connect("localhost", port=3306)  # OK
connect("localhost", 3306)       # Error
```

**Avoid Mutable Defaults:**
```python
# BAD
def append_to(item, items=[]):
    items.append(item)
    return items

# GOOD
def append_to(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

## Return Values
<!-- Lines 116-165 -->

Return values communicate function results. Be explicit and consistent.

**Return Type Patterns:**

| Pattern | Use Case | Example |
|---------|----------|---------|
| Single value | Most functions | `-> User` |
| Optional | May not find | `-> User | None` |
| Tuple | Multiple values | `-> tuple[int, str]` |
| NamedTuple | Named multiple | `-> UserResult` |
| Generator | Lazy sequence | `-> Iterator[User]` |

**Optional vs Exception:**
```python
# Optional: Failure is expected
def find_user(id: int) -> User | None:
    return users.get(id)

# Exception: Failure is unexpected
def get_user(id: int) -> User:
    user = users.get(id)
    if user is None:
        raise UserNotFoundError(id)
    return user
```

**Named Returns (for multiple values):**
```python
from typing import NamedTuple

class ParseResult(NamedTuple):
    value: int
    remainder: str

def parse_int(text: str) -> ParseResult:
    ...
    return ParseResult(value=42, remainder="abc")

# Usage
result = parse_int("42abc")
print(result.value)      # 42
print(result.remainder)  # "abc"
```

## Pure Functions
<!-- Lines 168-209 -->

Pure functions have no side effects and always return the same output for the same input.

**Characteristics:**
- No modification of external state
- No I/O operations
- Deterministic output
- Easy to test and reason about

**Pure vs Impure:**
```python
# Pure: Only depends on inputs
def calculate_discount(price: Decimal, rate: float) -> Decimal:
    return price * Decimal(str(rate))

# Impure: Depends on external state
def get_current_discount(price: Decimal) -> Decimal:
    rate = get_discount_rate_from_db()  # External dependency
    return price * rate
```

**Making Functions Purer:**
```python
# Before: Impure (uses global)
config = load_config()

def process(data):
    return transform(data, config.settings)

# After: Pure (explicit dependency)
def process(data, settings: Settings):
    return transform(data, settings)
```

**Benefits:**
- Easier to test (no setup needed)
- Easier to parallelize (no shared state)
- Easier to cache (same input = same output)
- Easier to reason about
