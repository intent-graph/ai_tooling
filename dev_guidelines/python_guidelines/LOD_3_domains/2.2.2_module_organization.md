## Packages vs Modules
<!-- Lines 18-56 -->

Understanding the distinction between packages and modules is fundamental to Python project organization.

**Definitions:**
- **Module**: Single `.py` file containing Python code
- **Package**: Directory containing `__init__.py` and modules

**Structure Example:**
```
my_package/               # Package (directory with __init__.py)
├── __init__.py          # Package initialization
├── core.py              # Module
├── models.py            # Module
└── utils/               # Subpackage
    ├── __init__.py
    └── helpers.py       # Module in subpackage
```

**Import Resolution:**
```python
# Module import
from my_package import core        # Imports core.py
from my_package.core import func   # Imports function from core.py

# Subpackage import
from my_package.utils import helpers
from my_package.utils.helpers import helper_func
```

**When to Use Subpackages:**
- Group related functionality
- Code exceeds ~1000 lines per module
- Clear architectural boundary exists

## __init__.py Patterns
<!-- Lines 59-109 -->

`__init__.py` defines what a package exports and runs at import time.

**Minimal (Recommended):**
```python
# my_package/__init__.py
"""Package description."""

__version__ = "0.1.0"
```

**Explicit Public API:**
```python
# my_package/__init__.py
"""Package with explicit exports."""

from my_package.core import process, transform
from my_package.models import Config, Result

__all__ = ["process", "transform", "Config", "Result"]
```

**Lazy Loading (For Large Packages):**
```python
# my_package/__init__.py
"""Lazy-loaded package for faster imports."""

def __getattr__(name: str):
    if name == "heavy_module":
        from my_package import heavy_module
        return heavy_module
    raise AttributeError(f"module {__name__!r} has no attribute {name!r}")
```

**Anti-Patterns:**

```python
# BAD: Star imports pollute namespace
from my_package.core import *
from my_package.models import *

# BAD: Heavy work at import time
import pandas as pd  # Don't import heavy deps in __init__.py
DATA = pd.read_csv("large_file.csv")  # Never do I/O at import
```

## Import Structure
<!-- Lines 112-173 -->

Consistent import organization improves readability and prevents conflicts.

**Import Order (PEP 8):**
```python
# 1. Standard library
import os
import sys
from pathlib import Path

# 2. Third-party packages
import httpx
from pydantic import BaseModel

# 3. Local application imports
from my_package.core import process
from my_package.models import Config
```

**Absolute vs Relative Imports:**

```python
# Absolute (Recommended for public API)
from my_package.utils.helpers import format_date

# Relative (Acceptable within package)
from .utils.helpers import format_date
from ..models import Config
```

**Import Styles:**

```python
# Direct import (preferred for functions/classes)
from my_package.models import User, Config

# Module import (when using many items)
from my_package import models
user = models.User()
config = models.Config()

# Aliased import (for long names or conflicts)
from my_package import long_module_name as lmn
import numpy as np
```

**Ruff Configuration:**
```toml
# pyproject.toml
[tool.ruff.lint]
select = ["I"]  # Enable isort rules

[tool.ruff.lint.isort]
known-first-party = ["my_package"]
force-single-line = true  # One import per line
```

## Circular Imports
<!-- Lines 176-244 -->

Circular imports occur when module A imports module B, and module B imports module A.

**The Problem:**
```python
# models.py
from my_package.services import UserService  # services.py imports models

class User:
    def get_service(self) -> UserService:
        return UserService(self)

# services.py
from my_package.models import User  # Circular!

class UserService:
    def __init__(self, user: User):
        self.user = user
```

**Solution 1: TYPE_CHECKING Block**
```python
# services.py
from __future__ import annotations
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from my_package.models import User

class UserService:
    def __init__(self, user: "User"):  # String annotation
        self.user = user
```

**Solution 2: Import at Function Level**
```python
# services.py
class UserService:
    def process_user(self):
        from my_package.models import User  # Import when needed
        return User()
```

**Solution 3: Restructure (Best)**
```python
# Better: Extract shared types to separate module
# types.py
from dataclasses import dataclass

@dataclass
class UserData:
    id: int
    name: str

# models.py
from my_package.types import UserData

# services.py
from my_package.types import UserData
```

**Prevention:**
- Keep modules focused (single responsibility)
- Use dependency injection over imports
- Extract shared types to dedicated modules
- Import interfaces, not implementations
