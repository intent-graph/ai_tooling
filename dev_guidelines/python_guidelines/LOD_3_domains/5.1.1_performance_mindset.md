## Core Concept
<!-- Lines 19-29 -->

Performance optimization is evidence-based engineering. Intuition about what's slow is usually wrong. Profile first, then optimize the actual bottleneck.

**The Performance Paradox:** Developers optimize what they think is slow, not what actually is slow. The function you spent hours micro-optimizing might take 0.1% of runtime.

## Premature Optimization
<!-- Lines 32-56 -->

"Premature optimization is the root of all evil" —Donald Knuth

This means: don't sacrifice readability for performance unless you have evidence it matters.

**Signs of Premature Optimization:**
- Optimizing without profiling
- Complex code "in case it's slow"
- Micro-optimizations in non-critical paths
- "It might be slow later"

**When to Optimize:**
- Profiling shows a bottleneck
- Performance doesn't meet requirements
- The code is stable (not actively changing)
- Benefits outweigh maintenance cost

**When NOT to Optimize:**
- During initial development
- Without measurement
- When readability suffers significantly
- For theoretical future needs

## Amdahl's Law
<!-- Lines 59-92 -->

Maximum speedup is limited by the proportion of time spent in the optimized part.

```
Speedup = 1 / ((1 - P) + P/S)

P = proportion of time in optimized section
S = speedup of that section
```

**Example:**
- Function takes 10% of runtime (P = 0.1)
- You make it infinitely fast (S = ∞)
- Maximum speedup: 1 / (1 - 0.1) = 1.11x (11% faster)

**Implications:**
- Focus on the biggest bottleneck first
- 2x speedup on 50% of code > 10x on 5%
- Sometimes the bottleneck is unavoidable (I/O, network)

**Practical Application:**
```python
# Profile shows:
# - Function A: 60% of time
# - Function B: 30% of time
# - Function C: 10% of time

# Optimize A first - maximum 2.5x potential
# Then B - additional ~1.4x potential
# C optimization is low priority
```

## Performance Budgets
<!-- Lines 95-133 -->

Define acceptable performance upfront. Testable criteria, not vague goals.

**Good Budgets:**
- API response < 200ms (p95)
- Page load < 3 seconds
- Memory usage < 512MB
- Startup time < 5 seconds

**Bad Budgets:**
- "Make it fast"
- "As fast as possible"
- "Good performance"

**Budget Tracking:**
```python
import time
import functools

def budget(max_seconds: float):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            start = time.perf_counter()
            result = func(*args, **kwargs)
            elapsed = time.perf_counter() - start
            if elapsed > max_seconds:
                logger.warning(f"{func.__name__} exceeded budget: {elapsed:.2f}s")
            return result
        return wrapper
    return decorator

@budget(0.2)
def api_endpoint():
```

## Optimization Workflow
<!-- Lines 136-169 -->

1. **Establish Baseline**
   - Measure current performance
   - Document conditions (data size, hardware)

2. **Profile**
   - Identify actual bottleneck
   - Don't guess—measure

3. **Hypothesize**
   - Why is this slow?
   - What would make it faster?

4. **Implement**
   - Change one thing at a time
   - Keep the old code (comment or branch)

5. **Measure**
   - Did it actually improve?
   - Any regressions elsewhere?

6. **Document**
   - Why the optimization was needed
   - What was changed
   - Before/after numbers

**Example:**
```python
# Before: O(n²) - 45 seconds for 10k items
# Bottleneck: Nested loop for lookups
# Solution: Convert inner list to set for O(1) lookup
# After: O(n) - 0.3 seconds for 10k items
# Speedup: 150x
```
