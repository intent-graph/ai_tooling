## Core Concept
<!-- Lines 17-31 -->

Debugging is systematic investigation, not random guessing. The best debuggers aren't the smartest—they're the most methodical.

**Debugging Mindset:**
- Assume the bug is in your code (usually is)
- Don't trust your assumptions
- Simplify and isolate
- Document what you try

## Scientific Debugging
<!-- Lines 34-84 -->

Apply the scientific method:

**1. Observe:**
What exactly is the bug? Reproduce it reliably.

```python
# Write a failing test
def test_bug_reproduction():
    result = buggy_function(specific_input)
    assert result == expected  # Fails consistently
```

**2. Hypothesize:**
What could cause this?

```
Possible causes:
- Off-by-one error in loop
- Null value not handled
- Race condition
- Incorrect assumption about input
```

**3. Test:**
Design experiment to confirm/refute.

```python
# Add targeted logging
def buggy_function(x):
    logger.debug(f"Input: {x}, type: {type(x)}")
    # ...
    logger.debug(f"After loop, value: {value}")
```

**4. Iterate:**
New evidence → new hypothesis → repeat.

**5. Fix and Verify:**
```python
def test_bug_fixed():
    # Original failing case
    assert buggy_function(specific_input) == expected

    # Related edge cases
    assert buggy_function(edge_case_1) == expected_1
    assert buggy_function(edge_case_2) == expected_2
```

## pdb Debugger
<!-- Lines 87-133 -->

Python's built-in debugger.

**Start Debugging:**
```python
# Insert breakpoint
breakpoint()  # Python 3.7+

# Or explicitly
import pdb; pdb.set_trace()
```

**Essential Commands:**
| Command | Action |
|---------|--------|
| `n` (next) | Execute next line |
| `s` (step) | Step into function |
| `c` (continue) | Run until next breakpoint |
| `r` (return) | Run until function returns |
| `p expr` | Print expression |
| `pp expr` | Pretty-print expression |
| `l` (list) | Show source code |
| `w` (where) | Show call stack |
| `u` (up) | Go up in call stack |
| `d` (down) | Go down in call stack |
| `q` (quit) | Exit debugger |

**Conditional Breakpoints:**
```python
for i, item in enumerate(items):
    if i == 50:  # Only break on 50th iteration
        breakpoint()
    process(item)
```

**Post-mortem Debugging:**
```python
import pdb

try:
    buggy_code()
except Exception:
    pdb.post_mortem()  # Debug at exception point
```

## IDE Debugging
<!-- Lines 136-178 -->

Visual debuggers provide richer inspection.

**VSCode:**
```json
// launch.json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Python: Current File",
            "type": "python",
            "request": "launch",
            "program": "${file}",
            "console": "integratedTerminal"
        }
    ]
}
```

**Features:**
- Click to set breakpoints
- Hover for variable values
- Watch expressions
- Call stack navigation
- Conditional breakpoints
- Logpoints (print without stopping)

**PyCharm:**
- Similar features
- Better Django/Flask integration
- Remote debugging built-in

**When to Use IDE vs pdb:**
| Situation | Tool |
|-----------|------|
| Complex state inspection | IDE |
| Remote server | pdb |
| Quick check | pdb/breakpoint() |
| New codebase exploration | IDE |

## Debugging Techniques
<!-- Lines 181-225 -->

**Binary Search Debugging:**
For "it worked, now it doesn't":

1. Find last known working state (commit, input)
2. Find current broken state
3. Test midpoint
4. Repeat until change identified

```bash
git bisect start
git bisect bad HEAD
git bisect good abc1234
# Git guides you to the breaking commit
```

**Rubber Duck Debugging:**
Explain the problem out loud. The act of articulating often reveals the answer.

**Minimal Reproduction:**
```python
# Reduce to smallest failing case
# From: Complex app with database, network, etc.
# To: Single function with hardcoded input

def minimal_reproduction():
    # Exact failing case, nothing else
    data = {"key": "specific_value"}
    result = problematic_function(data)
    print(result)  # Shows the bug
```

**Print Debugging (when appropriate):**
```python
def debug_function(x):
    print(f"DEBUG: Entering with x={x}")
    result = step_one(x)
    print(f"DEBUG: After step_one, result={result}")
    final = step_two(result)
    print(f"DEBUG: Final result={final}")
    return final
```

**Delta Debugging:**
Systematically reduce input until minimal failing case found.
