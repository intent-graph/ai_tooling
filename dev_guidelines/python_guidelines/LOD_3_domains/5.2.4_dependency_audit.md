## Core Concept
<!-- Lines 17-33 -->

Dependencies are code you didn't write but run with full privileges. A vulnerability in any dependency is a vulnerability in your application.

**Supply Chain Risks:**
- Known vulnerabilities (CVEs)
- Malicious packages (typosquatting)
- Abandoned packages
- Transitive dependencies

**The Log4Shell Example:** A single logging library vulnerability affected millions of applications. Your dependencies matter.

## Vulnerability Scanning
<!-- Lines 36-79 -->

**pip-audit:**
```bash
pip install pip-audit
pip-audit

# Output
Found 2 known vulnerabilities in 1 package(s)
Name    Version ID             Fix Versions
------- ------- -------------- ------------
urllib3 1.26.5  PYSEC-2021-108 1.26.5
```

**Safety:**
```bash
pip install safety
safety check

# With requirements file
safety check -r requirements.txt
```

**Snyk:**
```bash
snyk test
snyk monitor  # Continuous monitoring
```

**In CI Pipeline:**
```yaml
- name: Security scan
  run: |
    pip install pip-audit
    pip-audit --strict
```

**Handling Vulnerabilities:**
1. Check if vulnerability affects your usage
2. Update to fixed version if available
3. If no fix, consider alternatives or mitigations
4. Document accepted risks

## Automated Updates
<!-- Lines 82-125 -->

**Dependabot (GitHub):**
```yaml
# .github/dependabot.yml
version: 2
updates:
  - package-ecosystem: "pip"
    directory: "/"
    schedule:
      interval: "weekly"
    open-pull-requests-limit: 10
```

**Renovate:**
```json
// renovate.json
{
  "extends": ["config:base"],
  "pip_requirements": {
    "fileMatch": ["requirements.txt", "requirements-dev.txt"]
  }
}
```

**Update Strategy:**
| Update Type | Strategy |
|-------------|----------|
| Security patches | Merge immediately |
| Minor updates | Review, test, merge |
| Major updates | Plan migration |

**Pre-commit for Lock Files:**
```yaml
- repo: local
  hooks:
    - id: pip-audit
      name: pip-audit
      entry: pip-audit
      language: system
      pass_filenames: false
```

## Evaluating Dependencies
<!-- Lines 128-168 -->

Before adding a dependency:

**Checklist:**
- [ ] Is it actively maintained? (Recent commits)
- [ ] How many downloads? (Popularity)
- [ ] Known vulnerabilities?
- [ ] License compatible?
- [ ] How many dependencies does it bring?
- [ ] Can we implement it ourselves simply?

**Red Flags:**
- No releases in 2+ years
- Single maintainer
- No tests
- Obfuscated code
- Excessive permissions

**Typosquatting Prevention:**
```bash
# Verify package name carefully
pip install reqeusts  # Typo! Could be malicious
pip install requests  # Correct
```

**Minimal Dependencies:**
```python
# Instead of importing a library for one function
# Consider implementing simple utilities yourself

# Don't need 'humanize' for just this:
def humanize_bytes(size: int) -> str:
    for unit in ['B', 'KB', 'MB', 'GB']:
        if size < 1024:
            return f"{size:.1f} {unit}"
        size /= 1024
    return f"{size:.1f} TB"
```

## SBOM
<!-- Lines 171-204 -->

Software Bill of Materials—a complete dependency inventory.

**Generate SBOM:**
```bash
pip install cyclonedx-bom
cyclonedx-py -o sbom.json
```

**SBOM Contents:**
```json
{
  "bomFormat": "CycloneDX",
  "components": [
    {
      "name": "requests",
      "version": "2.31.0",
      "purl": "pkg:pypi/requests@2.31.0",
      "licenses": [{"license": {"id": "Apache-2.0"}}]
    }
  ]
}
```

**Why SBOM:**
- Vulnerability tracking
- License compliance
- Supply chain transparency
- Incident response

**Regulatory Requirements:**
- US Executive Order 14028 requires SBOM for government software
- Many enterprises now require SBOM from vendors
- Growing industry standard
