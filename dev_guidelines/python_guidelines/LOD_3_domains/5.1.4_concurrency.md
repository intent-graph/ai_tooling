## Core Concept
<!-- Lines 18-33 -->

Concurrency handles multiple tasks that overlap in time. One task waits (for network, disk) while another runs.

**I/O-bound vs CPU-bound:**
- **I/O-bound**: Waiting for external resources (network, disk, database)
- **CPU-bound**: Computing (math, image processing)

Threading helps I/O-bound work. For CPU-bound, use multiprocessing.

## The GIL
<!-- Lines 36-70 -->

Python's Global Interpreter Lock (GIL) allows only one thread to execute Python bytecode at a time.

**What GIL Means:**
- CPU-bound threads don't run in parallel
- I/O-bound threads work fine (GIL released during I/O)
- C extensions can release GIL

**I/O Releases GIL:**
```python
# These operations release the GIL:
response = requests.get(url)  # Network wait
data = file.read()            # Disk wait
cursor.execute(query)         # Database wait

# Other threads run while waiting
```

**CPU-bound GIL Contention:**
```python
# Both threads fight for GIL
def compute(n):
    return sum(i * i for i in range(n))

# No parallel speedup with threading
# Use multiprocessing instead
```

**GIL Workarounds:**
- `multiprocessing` for CPU-bound
- NumPy/pandas release GIL for vectorized ops
- C extensions with nogil

## threading Module
<!-- Lines 73-118 -->

Low-level threading interface.

**Basic Thread:**
```python
import threading

def worker(url):
    response = requests.get(url)
    return response.text

thread = threading.Thread(target=worker, args=(url,))
thread.start()
thread.join()  # Wait for completion
```

**Multiple Threads:**
```python
threads = []
for url in urls:
    t = threading.Thread(target=fetch, args=(url,))
    t.start()
    threads.append(t)

for t in threads:
    t.join()
```

**Thread with Return Value:**
```python
import queue

result_queue = queue.Queue()

def worker(url, result_queue):
    result = requests.get(url).text
    result_queue.put(result)

thread = threading.Thread(target=worker, args=(url, result_queue))
thread.start()
thread.join()
result = result_queue.get()
```

## concurrent.futures
<!-- Lines 121-157 -->

High-level interface for thread pools. Preferred over raw threading.

**ThreadPoolExecutor:**
```python
from concurrent.futures import ThreadPoolExecutor, as_completed

def fetch(url):
    return requests.get(url).json()

with ThreadPoolExecutor(max_workers=10) as executor:
    # Submit all tasks
    futures = {executor.submit(fetch, url): url for url in urls}

    # Process as they complete
    for future in as_completed(futures):
        url = futures[future]
        try:
            data = future.result()
            print(f"{url}: {len(data)} bytes")
        except Exception as e:
            print(f"{url}: {e}")
```

**executor.map (simpler):**
```python
with ThreadPoolExecutor(max_workers=10) as executor:
    results = list(executor.map(fetch, urls))
```

**Choosing max_workers:**
- I/O-bound: 10-100 workers
- Mixed: 5-20 workers
- Default: min(32, cpu_count + 4)

## Thread Safety
<!-- Lines 160-201 -->

Shared mutable state + threads = bugs.

**Race Condition:**
```python
# Broken: Race condition
counter = 0

def increment():
    global counter
    counter += 1  # Read, add, write - not atomic

# Fix: Use Lock
lock = threading.Lock()

def increment_safe():
    global counter
    with lock:
        counter += 1
```

**Thread-safe Collections:**
```python
from queue import Queue

# Thread-safe queue
q = Queue()
q.put(item)
item = q.get()
```

**Best Practices:**
- Avoid shared mutable state
- Use queues for inter-thread communication
- Use locks when sharing is unavoidable
- Prefer `concurrent.futures` over raw threads
- Consider immutable data structures

**Deadlock Prevention:**
- Always acquire locks in the same order
- Use timeouts: `lock.acquire(timeout=5)`
- Use `RLock` for recursive locking
