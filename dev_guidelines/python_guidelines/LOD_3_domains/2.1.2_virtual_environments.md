## Why Isolation
<!-- Lines 16-47 -->

Virtual environments solve dependency conflicts by giving each project its own package namespace.

**The Problem:**
```
Global Python
├── Project A needs requests==2.28.0
├── Project B needs requests==2.31.0
└── Conflict: Only one version can exist
```

**The Solution:**
```
Project A/.venv/
└── requests==2.28.0

Project B/.venv/
└── requests==2.31.0
```

**Isolation Benefits:**
- No version conflicts between projects
- Reproducible environments
- Clean uninstall (delete the folder)
- Match production exactly

## venv Module
<!-- Lines 50-99 -->

`venv` is Python's built-in virtual environment tool. Use it unless you have specific reasons not to.

**Create Environment:**
```bash
# Standard location
python -m venv .venv

# Custom location
python -m venv ~/envs/project_name
```

**Activate:**
```bash
# Unix/macOS (bash/zsh)
source .venv/bin/activate

# Windows (cmd)
.venv\Scripts\activate.bat

# Windows (PowerShell)
.venv\Scripts\Activate.ps1

# Fish shell
source .venv/bin/activate.fish
```

**Deactivate:**
```bash
deactivate
```

**Environment Contents:**
```
.venv/
├── bin/           # Unix executables
│   ├── activate
│   ├── python -> python3.12
│   └── pip
├── lib/           # Installed packages
│   └── python3.12/site-packages/
├── include/       # C headers (for compilation)
└── pyvenv.cfg     # Environment metadata
```

## Environment Tools
<!-- Lines 102-146 -->

**Tool Comparison:**

| Tool | Use Case | Key Feature |
|------|----------|-------------|
| venv | Standard | Built-in, simple |
| virtualenv | Advanced | Faster, more options |
| conda | Scientific | System packages, environments |

**venv (Recommended):**
```bash
python -m venv .venv
```

**virtualenv:**
```bash
# Install once
pip install virtualenv

# Create (faster than venv)
virtualenv .venv
```

**conda:**
```bash
# Create with specific Python
conda create -n myproject python=3.12

# Activate
conda activate myproject

# Install non-Python packages
conda install numpy scipy
```

**When to Use What:**
- **venv**: 99% of projects
- **virtualenv**: Need speed or Python 2 support
- **conda**: Scientific computing, need system libraries (CUDA, MKL)

## Best Practices
<!-- Lines 149-214 -->

**Naming Convention:**
```bash
# Standard: .venv in project root
project/
└── .venv/

# Alternative: venv (visible)
project/
└── venv/
```

**Gitignore:**
```gitignore
# .gitignore
.venv/
venv/
*.egg-info/
```

**Activation in Scripts:**
```bash
#!/bin/bash
# scripts/run.sh
source .venv/bin/activate
python -m myproject "$@"
```

**VS Code Integration:**
```json
// .vscode/settings.json
{
    "python.defaultInterpreterPath": "${workspaceFolder}/.venv/bin/python"
}
```

**Dependency Pinning:**
```bash
# After installing packages
pip freeze > requirements.txt

# Better: Use pyproject.toml + lock file
uv pip compile pyproject.toml -o requirements.lock
```

**Environment Verification:**
```bash
# Check active environment
which python
# Should show: /path/to/project/.venv/bin/python

# Check installed packages
pip list
```

**Environment Recreation:**
```bash
# Delete and recreate
rm -rf .venv
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```
