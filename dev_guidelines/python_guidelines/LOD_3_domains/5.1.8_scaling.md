## Core Concept
<!-- Lines 17-36 -->

When single-machine optimization isn't enough, scale out the architecture.

**Scaling Triggers:**
- Response times exceed SLAs
- Single server at capacity
- Need for redundancy/reliability
- Geographic distribution

**Scaling Dimensions:**
- Compute (more CPU)
- Memory (more RAM)
- Storage (more disk/DB capacity)
- Network (more bandwidth)

**Cross-refs:**
- ↑ Parent: [5.1 Performance](../LOD_2_phases/5.1_performance.md)

## Vertical vs Horizontal
<!-- Lines 39-75 -->

**Vertical Scaling (Scale Up):**
Bigger machine—more CPU, RAM, faster disk.

Pros:
- Simple (no code changes)
- No distributed complexity

Cons:
- Hardware limits
- Single point of failure
- Expensive at high end

**Horizontal Scaling (Scale Out):**
More machines sharing the load.

Pros:
- Near-unlimited scale
- Redundancy built-in
- Cost-effective

Cons:
- Distributed system complexity
- Data consistency challenges
- Network overhead

**When to Choose:**
```
Single server sufficient? → Vertical
Need > 1 machine capacity? → Horizontal
Need high availability? → Horizontal
Simple application? → Vertical first
Stateless application? → Horizontal friendly
```

## Worker Queues
<!-- Lines 78-125 -->

Decouple work producers from consumers using message queues.

**Architecture:**
```
[Web Server] → [Redis Queue] → [Worker 1]
                            → [Worker 2]
                            → [Worker N]
```

**Celery Example:**
```python
from celery import Celery

app = Celery('tasks', broker='redis://localhost')

@app.task
def process_order(order_id):
    order = Order.get(order_id)
    # Long-running processing
    return result

# Enqueue task
process_order.delay(order_id)  # Returns immediately
```

**RQ (simpler):**
```python
from rq import Queue
from redis import Redis

q = Queue(connection=Redis())

def process(data):
    return heavy_computation(data)

job = q.enqueue(process, data)
```

**When to Use Queues:**
- Long-running tasks
- Batch processing
- Decoupling components
- Rate limiting
- Retry handling

## Caching Layers
<!-- Lines 128-183 -->

Cache frequently accessed data closer to users.

**Caching Hierarchy:**
```
[Client Cache] → [CDN] → [App Cache] → [DB Cache] → [Database]
     ↑              ↑          ↑            ↑
   Browser       Edge      Redis/Memcached  Query Cache
```

**Redis Caching:**
```python
import redis
import json

r = redis.Redis()

def get_user(user_id: int) -> dict:
    # Check cache
    cached = r.get(f"user:{user_id}")
    if cached:
        return json.loads(cached)

    # Cache miss - fetch from DB
    user = db.query(User).get(user_id)
    r.setex(
        f"user:{user_id}",
        3600,  # TTL: 1 hour
        json.dumps(user.to_dict())
    )
    return user.to_dict()
```

**Cache Invalidation Strategies:**
| Strategy | Description |
|----------|-------------|
| TTL | Expire after time |
| Write-through | Update cache on write |
| Write-behind | Async cache update |
| Cache-aside | App manages cache |

**Cache Stampede Prevention:**
```python
# Use lock to prevent multiple DB queries
lock = redis.Lock(f"lock:user:{user_id}")
if lock.acquire(blocking=True, timeout=5):
    try:
        # Only one process fetches
        user = fetch_from_db(user_id)
        cache.set(f"user:{user_id}", user)
    finally:
        lock.release()
```

## Design Principles
<!-- Lines 186-230 -->

**Stateless Applications:**
Store state externally (database, cache, session store). Any instance can handle any request.

```python
# Bad: In-memory state
class App:
    def __init__(self):
        self.sessions = {}  # Lost on restart, not shared

# Good: External state
class App:
    def __init__(self, redis_client):
        self.redis = redis_client

    def get_session(self, session_id):
        return self.redis.get(f"session:{session_id}")
```

**Idempotent Operations:**
Safe to retry without side effects.

```python
# Not idempotent
def charge_card(order_id, amount):
    payment_api.charge(amount)  # Charges again on retry!

# Idempotent
def charge_card(order_id, amount):
    if Order.get(order_id).is_paid:
        return  # Already processed
    payment_api.charge(amount, idempotency_key=order_id)
    Order.get(order_id).mark_paid()
```

**Circuit Breakers:**
Prevent cascading failures from failing services.

```python
from circuitbreaker import circuit

@circuit(failure_threshold=5, recovery_timeout=30)
def call_external_service():
    return requests.get(url, timeout=5)
```
