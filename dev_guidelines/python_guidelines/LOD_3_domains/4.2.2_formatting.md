## Core Concept
<!-- Lines 17-38 -->

Formatters rewrite code to a canonical style. They eliminate style debates—the formatter decides, humans accept.

**Philosophy:**
- Consistency over personal preference
- No configuration (or minimal)
- Deterministic output
- Fast enough to run on save

**What Formatters Handle:**
- Whitespace and indentation
- Line length and wrapping
- Quote style
- Trailing commas
- Blank lines

## Black
<!-- Lines 41-83 -->

Black is "the uncompromising code formatter." It has minimal configuration by design.

**Installation:**
```bash
pip install black
```

**Usage:**
```bash
black .                    # Format all Python files
black --check .            # Check without modifying
black --diff .             # Show what would change
black src/module.py        # Format single file
```

**Configuration:**
```toml
[tool.black]
line-length = 88
target-version = ["py310"]
include = '\.pyi?$'
extend-exclude = '''
/(
    migrations
    | generated
)/
'''
```

**Black's Decisions:**
- Double quotes for strings
- Trailing commas in multi-line structures
- One statement per line
- Blank lines between definitions

**Intentional Non-configurability:**
- Quote style: Double quotes (not configurable)
- Line length: 88 is the only option worth discussing
- Everything else: Black decides

## Ruff Format
<!-- Lines 86-121 -->

Ruff includes a Black-compatible formatter that's 100x faster.

**Usage:**
```bash
ruff format .              # Format all files
ruff format --check .      # Check without modifying
ruff format --diff .       # Show changes
```

**Configuration:**
```toml
[tool.ruff.format]
quote-style = "double"
indent-style = "space"
line-ending = "auto"
```

**Black Compatibility:**
Ruff format aims for near-100% compatibility with Black. Minor differences exist but are rare.

**Benefits over Black:**
- Part of the Ruff tool (one fewer dependency)
- 10-100x faster
- Same configuration file

**Migration:**
```bash
# Check for differences
black . --check
ruff format --check .
# If both pass, they produce same output
```

## Import Sorting
<!-- Lines 124-164 -->

Import sorting is typically handled by the linter (Ruff with `I` rules), not the formatter.

**Ruff isort:**
```toml
[tool.ruff.lint]
select = ["I"]

[tool.ruff.lint.isort]
known-first-party = ["mypackage"]
section-order = [
    "future",
    "standard-library",
    "third-party",
    "first-party",
    "local-folder"
]
```

**Import Order:**
```python
# 1. Future imports
from __future__ import annotations

# 2. Standard library
import os
from pathlib import Path

# 3. Third-party
import httpx
from pydantic import BaseModel

# 4. First-party (your package)
from mypackage.core import Engine
from mypackage.utils import helpers
```

**Sorting within sections:** Alphabetical by default.

## Integration
<!-- Lines 167-199 -->

**Editor Integration:**

VSCode settings.json:
```json
{
    "[python]": {
        "editor.formatOnSave": true,
        "editor.defaultFormatter": "charliermarsh.ruff"
    }
}
```

**Pre-commit:**
```yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.1.6
    hooks:
      - id: ruff-format
```

**CI Check:**
```yaml
- name: Check formatting
  run: ruff format --check .
```

**Workflow:**
1. Format on save in editor
2. Pre-commit catches anything missed
3. CI enforces in PR
4. Never debate formatting in code review
