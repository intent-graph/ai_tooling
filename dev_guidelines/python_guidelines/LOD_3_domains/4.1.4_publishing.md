## Core Concept
<!-- Lines 17-29 -->

Publishing makes your package installable via `pip install packagename`. The primary target is PyPI (Python Package Index), but organizations often maintain private indexes for internal packages.

**Publishing Flow:**
1. Build artifacts (`python -m build`)
2. Test on TestPyPI (optional but recommended)
3. Upload to PyPI

## PyPI Publishing
<!-- Lines 32-73 -->

**Manual Upload with Twine:**
```bash
# Build
python -m build

# Upload to TestPyPI first
twine upload --repository testpypi dist/*

# Test installation
pip install --index-url https://test.pypi.org/simple/ mypackage

# Upload to production PyPI
twine upload dist/*
```

**Configuration (~/.pypirc):**
```ini
[pypi]
username = __token__
password = pypi-xxxxx

[testpypi]
repository = https://test.pypi.org/legacy/
username = __token__
password = pypi-xxxxx
```

**API Tokens:**
- Create at pypi.org/manage/account/token/
- Scope to specific project when possible
- Store securely (environment variable, secrets manager)

**Common Errors:**
| Error | Cause | Fix |
|-------|-------|-----|
| 403 Forbidden | Invalid token | Regenerate token |
| File already exists | Version already published | Bump version |
| Invalid classifier | Typo in classifier | Check against PyPI list |

## Trusted Publishing
<!-- Lines 76-123 -->

Trusted publishing uses OIDC (OpenID Connect) to authenticate from CI systems. No API tokens to manage or rotate.

**GitHub Actions Setup:**

1. Configure on PyPI:
   - Go to project settings → Publishing
   - Add GitHub Actions as trusted publisher
   - Specify repository, workflow, environment

2. Workflow configuration:
```yaml
name: Publish to PyPI
on:
  release:
    types: [published]

jobs:
  publish:
    runs-on: ubuntu-latest
    environment: release
    permissions:
      id-token: write  # Required for OIDC

    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Build
        run: |
          pip install build
          python -m build

      - name: Publish to PyPI
        uses: pypa/gh-action-pypi-publish@release/v1
        # No credentials needed!
```

**Benefits:**
- No secrets to manage
- Cannot be leaked
- Scoped to specific workflows
- Audit trail of who published what

## Private Indexes
<!-- Lines 126-167 -->

For internal packages not suitable for public PyPI.

**Options:**
| Solution | Complexity | Features |
|----------|------------|----------|
| Simple file server | Low | Basic hosting |
| devpi | Medium | Caching, staging |
| AWS CodeArtifact | Medium | AWS integration |
| GCP Artifact Registry | Medium | GCP integration |
| Artifactory | High | Enterprise features |

**Installing from Private Index:**
```bash
# Single package
pip install --index-url https://private.example.com/simple/ mypackage

# All packages (pip.conf)
[global]
index-url = https://private.example.com/simple/
extra-index-url = https://pypi.org/simple/
```

**Publishing to Private Index:**
```bash
twine upload --repository-url https://private.example.com/simple/ dist/*
```

**devpi Setup:**
```bash
# Server
devpi-server --start --init

# Client
devpi use http://localhost:3141
devpi login root --password=''
devpi index -c dev
devpi upload
```

## Pre-flight Checklist
<!-- Lines 170-199 -->

Before publishing:

**Metadata:**
- [ ] Package name available (check pypi.org)
- [ ] Version follows PEP 440
- [ ] Description is accurate
- [ ] README renders correctly (test on TestPyPI)
- [ ] License classifier matches LICENSE file
- [ ] URLs point to correct locations

**Quality:**
- [ ] Tests pass
- [ ] Linting passes
- [ ] Type checking passes
- [ ] Documentation builds

**Security:**
- [ ] No secrets in code
- [ ] No unnecessary files in sdist
- [ ] Dependencies have no known vulnerabilities

**Test Installation:**
```bash
# Test in isolated environment
python -m venv /tmp/test-env
source /tmp/test-env/bin/activate
pip install dist/*.whl
python -c "import mypackage; print(mypackage.__version__)"
```
