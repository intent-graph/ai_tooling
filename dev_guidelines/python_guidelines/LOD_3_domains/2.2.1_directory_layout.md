## Layout Patterns
<!-- Lines 17-48 -->

Three directory layouts dominate Python projects. Choose based on distribution needs and project complexity.

**Decision Matrix:**

| Layout | Best For | Distribution |
|--------|----------|--------------|
| src-layout | Libraries, packages | PyPI |
| Flat | Applications, internal tools | Container/deploy |
| Monorepo | Multi-package projects | Mixed |

**Key Principle:**
Project layout should prevent accidental imports of uninstalled code. The src-layout accomplishes this by forcing installed imports during development.

**Common Structure:**
```
project_name/
├── src/ or project_name/  # Source code
├── tests/                  # Test suite
├── docs/                   # Documentation
├── scripts/               # Utility scripts
├── pyproject.toml         # Project metadata
├── README.md              # Overview
└── .gitignore             # Git exclusions
```

## src-layout
<!-- Lines 51-99 -->

The src-layout places package code inside a `src/` directory. This is the recommended layout for distributable packages.

**Structure:**
```
my_package/
├── src/
│   └── my_package/
│       ├── __init__.py
│       ├── core.py
│       ├── models.py
│       └── utils/
│           ├── __init__.py
│           └── helpers.py
├── tests/
│   ├── __init__.py
│   ├── conftest.py
│   └── test_core.py
├── pyproject.toml
└── README.md
```

**Why src-layout:**
- Prevents importing uninstalled code
- Tests always import the installed package
- Clean separation of source and project files
- Standard for PyPI packages

**Import Behavior:**
```python
# Without installation: ImportError
# This prevents "works locally, breaks on install"
from my_package import core  # Only works after pip install

# Tests use installed version
# pytest tests/  # Uses installed my_package
```

**pyproject.toml Configuration:**
```toml
[tool.setuptools.packages.find]
where = ["src"]
```

## Flat Layout
<!-- Lines 102-143 -->

The flat layout places the package directly in the project root. Simpler but less isolated.

**Structure:**
```
my_project/
├── my_project/
│   ├── __init__.py
│   ├── core.py
│   └── models.py
├── tests/
│   └── test_core.py
├── pyproject.toml
└── README.md
```

**When to Use:**
- Internal applications (not distributed to PyPI)
- Simple scripts and tools
- Rapid prototyping
- Single-package projects

**Tradeoffs:**
| Aspect | Flat | src-layout |
|--------|------|------------|
| Simplicity | Better | More setup |
| Import safety | Risk | Protected |
| Distribution | Possible | Recommended |
| Testing | Can import local | Always installed |

**pyproject.toml Configuration:**
```toml
[tool.setuptools.packages.find]
where = ["."]
exclude = ["tests*"]
```

## Monorepo Layout
<!-- Lines 146-194 -->

Monorepos contain multiple related packages in a single repository.

**Structure:**
```
monorepo/
├── packages/
│   ├── core/
│   │   ├── src/core/
│   │   │   ├── __init__.py
│   │   │   └── logic.py
│   │   ├── tests/
│   │   └── pyproject.toml
│   ├── api/
│   │   ├── src/api/
│   │   │   ├── __init__.py
│   │   │   └── routes.py
│   │   ├── tests/
│   │   └── pyproject.toml
│   └── cli/
│       ├── src/cli/
│       └── pyproject.toml
├── pyproject.toml          # Workspace root
├── README.md
└── .github/
```

**Workspace Configuration:**
```toml
# Root pyproject.toml (uv/hatch workspace)
[tool.uv.workspace]
members = ["packages/*"]

# Package dependencies
[tool.uv.sources]
core = { workspace = true }
```

**When to Use:**
- Multiple packages with shared dependencies
- Tight coupling between packages
- Unified versioning and releases
- Shared CI/CD pipeline

## Supporting Files
<!-- Lines 197-250 -->

Standard files that accompany Python projects.

**Required Files:**

| File | Purpose |
|------|---------|
| `pyproject.toml` | Project metadata, dependencies, tool config |
| `README.md` | Project overview and quick start |
| `.gitignore` | Git exclusions |

**Recommended Files:**

| File | Purpose |
|------|---------|
| `LICENSE` | Legal terms |
| `CHANGELOG.md` | Version history |
| `CONTRIBUTING.md` | Contributor guidelines |
| `.pre-commit-config.yaml` | Git hooks |
| `Makefile` | Common tasks |

**Recommended Directories:**

```
project/
├── .github/             # GitHub workflows and templates
│   └── workflows/
├── docs/                # Documentation (Sphinx/MkDocs)
├── scripts/             # Utility scripts
└── examples/            # Usage examples
```

**Standard .gitignore:**
```gitignore
# Python
__pycache__/
*.py[cod]
*.egg-info/
dist/
build/

# Environment
.venv/
.env

# IDE
.vscode/settings.local.json
.idea/

# Testing
.pytest_cache/
.coverage
htmlcov/
```
