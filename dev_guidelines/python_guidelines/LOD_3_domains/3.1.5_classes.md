## When to Use Classes
<!-- Lines 16-63 -->

Classes are appropriate when you have data with associated behavior or invariants to maintain.

**Use Classes When:**
- Data has invariants (validation rules)
- Multiple operations on same data
- Need encapsulation (hide implementation)
- Implementing a defined interface

**Avoid Classes When:**
- Only grouping data (use dataclass or NamedTuple)
- Only grouping functions (use module)
- Single-use behavior (use function)

**Class vs Function:**
```python
# Overkill: Class for simple operation
class Adder:
    def add(self, a, b):
        return a + b

# Better: Just a function
def add(a, b):
    return a + b
```

**Class vs Module:**
```python
# Overkill: Class with only static methods
class MathUtils:
    @staticmethod
    def add(a, b): return a + b

    @staticmethod
    def multiply(a, b): return a * b

# Better: Module with functions
# math_utils.py
def add(a, b): return a + b
def multiply(a, b): return a * b
```

## Dataclasses
<!-- Lines 66-130 -->

Dataclasses reduce boilerplate for data-holding classes.

**Basic Dataclass:**
```python
from dataclasses import dataclass

@dataclass
class User:
    id: int
    name: str
    email: str
```

**With Defaults:**
```python
@dataclass
class User:
    id: int
    name: str
    email: str = ""
    active: bool = True
```

**Frozen (Immutable):**
```python
@dataclass(frozen=True)
class Point:
    x: float
    y: float

p = Point(1.0, 2.0)
p.x = 3.0  # Error: frozen
```

**With Validation:**
```python
@dataclass
class User:
    id: int
    name: str
    email: str

    def __post_init__(self):
        if not self.name:
            raise ValueError("Name cannot be empty")
        if "@" not in self.email:
            raise ValueError("Invalid email")
```

**Field Factories:**
```python
from dataclasses import dataclass, field

@dataclass
class Order:
    items: list[str] = field(default_factory=list)
    metadata: dict = field(default_factory=dict)
```

## Protocols
<!-- Lines 133-189 -->

Protocols define interfaces through structural subtyping (duck typing with type checking).

**Define Protocol:**
```python
from typing import Protocol

class Repository(Protocol):
    def get(self, id: int) -> User: ...
    def save(self, user: User) -> None: ...
    def delete(self, id: int) -> None: ...
```

**Implement Protocol:**
```python
# No explicit inheritance needed
class PostgresRepository:
    def get(self, id: int) -> User:
        return self.db.query(User).get(id)

    def save(self, user: User) -> None:
        self.db.add(user)

    def delete(self, id: int) -> None:
        self.db.delete(User, id)

# Type checker accepts this as Repository
def process(repo: Repository) -> None:
    user = repo.get(1)
    ...
```

**Protocol vs ABC:**
```python
# ABC: Requires inheritance
from abc import ABC, abstractmethod

class Repository(ABC):
    @abstractmethod
    def get(self, id: int) -> User: ...

class PostgresRepo(Repository):  # Must inherit
    ...

# Protocol: Structural matching
class Repository(Protocol):
    def get(self, id: int) -> User: ...

class PostgresRepo:  # No inheritance needed
    def get(self, id: int) -> User: ...
```

## Inheritance vs Composition
<!-- Lines 192-244 -->

Prefer composition over inheritance in most cases.

**Inheritance Problems:**
- Tight coupling to parent
- Fragile base class problem
- Diamond problem with multiple inheritance
- Hard to change parent without breaking children

**Composition Example:**
```python
# Instead of inheritance
class FileLogger(Logger):
    def log(self, msg): ...

class DatabaseLogger(Logger):
    def log(self, msg): ...

# Use composition
class Logger:
    def __init__(self, writer: Writer):
        self.writer = writer

    def log(self, msg: str) -> None:
        self.writer.write(f"[LOG] {msg}")

# Inject different writers
file_logger = Logger(FileWriter("app.log"))
db_logger = Logger(DatabaseWriter(connection))
```

**When Inheritance Works:**
- True "is-a" relationship
- Framework requires it (Django models)
- Abstract base classes for shared implementation

**Mixin Pattern (Limited Inheritance):**
```python
class TimestampMixin:
    created_at: datetime
    updated_at: datetime

    def touch(self) -> None:
        self.updated_at = datetime.now()

@dataclass
class User(TimestampMixin):
    name: str
```
