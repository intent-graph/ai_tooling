## Core Concept
<!-- Lines 17-30 -->

`pyproject.toml` is Python's standard project configuration file (PEP 518, PEP 621). It replaces the fragmented configuration landscape of `setup.py`, `setup.cfg`, `MANIFEST.in`, and scattered tool configs.

**Benefits:**
- Single file for all project metadata
- Declarative (no executable code)
- Tool-agnostic (any build backend can read it)
- Human-readable TOML format

## Project Metadata
<!-- Lines 33-72 -->

The `[project]` table defines package metadata per PEP 621.

```toml
[project]
name = "mypackage"
version = "1.0.0"
description = "Short description of what this does"
readme = "README.md"
requires-python = ">=3.10"
license = {text = "MIT"}
authors = [
    {name = "Author Name", email = "author@example.com"}
]
keywords = ["cli", "automation"]
classifiers = [
    "Development Status :: 4 - Beta",
    "Programming Language :: Python :: 3.10",
    "Programming Language :: Python :: 3.11",
]

dependencies = [
    "httpx>=0.24",
    "pydantic>=2.0,<3.0",
]

[project.optional-dependencies]
dev = ["pytest>=7.0", "ruff>=0.1"]
docs = ["sphinx>=6.0", "furo"]

[project.urls]
Homepage = "https://github.com/user/mypackage"
Documentation = "https://mypackage.readthedocs.io"

[project.scripts]
mycommand = "mypackage.cli:main"
```

## Build System
<!-- Lines 75-108 -->

The `[build-system]` table specifies how to build the package.

```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"
```

**Required Fields:**
- `requires`: Build-time dependencies
- `build-backend`: Module path to the backend

**Common Backends:**
```toml
# Hatchling (recommended)
requires = ["hatchling"]
build-backend = "hatchling.build"

# Setuptools
requires = ["setuptools>=61", "wheel"]
build-backend = "setuptools.build_meta"

# Flit
requires = ["flit_core>=3.4"]
build-backend = "flit_core.buildapi"

# Poetry
requires = ["poetry-core>=1.0"]
build-backend = "poetry.core.masonry.api"
```

## Tool Configuration
<!-- Lines 111-141 -->

The `[tool.*]` namespace holds configuration for development tools.

```toml
[tool.ruff]
line-length = 88
target-version = "py310"

[tool.ruff.lint]
select = ["E", "F", "I", "B", "UP"]

[tool.mypy]
python_version = "3.10"
strict = true

[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "-ra -q"

[tool.coverage.run]
source = ["src/mypackage"]
branch = true

[tool.hatch.build.targets.wheel]
packages = ["src/mypackage"]
```

**Convention:** Each tool uses `[tool.toolname]` namespace.

## Dynamic Fields
<!-- Lines 144-175 -->

Some fields can be computed at build time instead of hardcoded.

```toml
[project]
dynamic = ["version"]

# Version from __init__.py
[tool.hatch.version]
path = "src/mypackage/__init__.py"

# Version from git tags
[tool.hatch.version]
source = "vcs"

# README as description
[project]
dynamic = ["readme"]
[tool.hatch.metadata]
readme = "README.md"
```

**Dynamically Supported Fields:**
- `version`: Most commonly dynamic
- `readme`: Long description
- `dependencies`: Rarely dynamic

**Version in __init__.py:**
```python
# src/mypackage/__init__.py
__version__ = "1.0.0"
```
