## Core Concept
<!-- Lines 16-30 -->

Security is a mindset, not a checklist. It requires thinking adversarially: "How could this be abused?" rather than "How does this work?"

**Security vs Features:**
- Features: "How do I make this work?"
- Security: "How could this break? What if the user is malicious?"

**Defense in Depth:** Multiple security layers. If one fails, others still protect.

## Security Principles
<!-- Lines 33-76 -->

**Principle of Least Privilege:**
Grant minimum necessary permissions.

```python
# Bad: Admin database user for everything
db_user = "admin"

# Good: Read-only user for read operations
read_user = "readonly_user"
write_user = "write_user"
```

**Defense in Depth:**
Multiple layers of protection.

```python
# Layer 1: Input validation
user_input = validate(raw_input)

# Layer 2: Parameterized query
cursor.execute("SELECT * FROM users WHERE id = %s", (user_input,))

# Layer 3: Minimal database permissions
# User can only SELECT, not DROP
```

**Fail Securely:**
Errors should not reveal information or grant access.

```python
# Bad: Reveals user existence
if not user:
    raise Error("User not found")
if not check_password(password):
    raise Error("Wrong password")

# Good: Generic error
if not user or not check_password(user, password):
    raise Error("Invalid credentials")
```

## Threat Modeling
<!-- Lines 79-109 -->

**STRIDE Framework:**
| Threat | Description | Mitigation |
|--------|-------------|------------|
| **S**poofing | Pretending to be someone else | Authentication |
| **T**ampering | Modifying data | Integrity checks |
| **R**epudiation | Denying actions | Audit logging |
| **I**nformation Disclosure | Data leaks | Encryption, access control |
| **D**enial of Service | Making unavailable | Rate limiting |
| **E**levation of Privilege | Gaining unauthorized access | Authorization |

**Questions to Ask:**
1. What are we protecting? (Assets)
2. Who might attack? (Threat actors)
3. How might they attack? (Attack vectors)
4. What's the impact? (Risk)
5. How do we mitigate? (Controls)

**Attack Surface:**
```
Entry Points:
- HTTP endpoints
- Form inputs
- File uploads
- API parameters
- Environment variables
- Database queries
```

## Common Mistakes
<!-- Lines 112-158 -->

**Security Through Obscurity:**
```python
# Bad: Hidden endpoint is "secure"
@app.route('/secret-admin-panel-12345')
def admin():
    return admin_panel()  # No auth!

# Good: Proper authentication
@app.route('/admin')
@require_admin
def admin():
    return admin_panel()
```

**Client-Side Validation Only:**
```python
# Bad: Trusting client validation
@app.route('/purchase', methods=['POST'])
def purchase():
    price = request.form['price']  # User-controlled!
    charge_card(price)

# Good: Server-side validation
@app.route('/purchase', methods=['POST'])
def purchase():
    item = get_item(request.form['item_id'])
    charge_card(item.price)  # Server-determined
```

**Logging Sensitive Data:**
```python
# Bad
logger.info(f"User login: {username}, password: {password}")

# Good
logger.info(f"User login attempt: {username}")
```

**Hardcoded Secrets:**
```python
# Bad
API_KEY = "sk-12345abcde"

# Good
API_KEY = os.environ["API_KEY"]
```
