## Core Concept
<!-- Lines 35-56 -->

**Definition:** Success criteria are measurable, verifiable conditions that define when a project or feature is "done" and successful.

**Key Points:**
- Criteria must be measurable (numbers, not feelings)
- Criteria must be verifiable (can be tested)
- Criteria should cover functional, technical, and business aspects
- Criteria become acceptance tests

**SMART Criteria:**
- **S**pecific: Clear what it means
- **M**easurable: Can quantify it
- **A**chievable: Possible to meet
- **R**elevant: Matters to stakeholders
- **T**ime-bound: When it must be met

## When to Use
<!-- Lines 59-79 -->

**Use When:**
- Defining project requirements
- Planning a feature or release
- Creating acceptance tests
- Evaluating project success
- Negotiating with stakeholders

**Define Early:**
- Before design begins
- Before implementation starts
- Before "done" is ambiguous

**Warning Signs of Missing Criteria:**
- "Is this done?" has no clear answer
- Stakeholders disagree on success
- Features ship but aren't considered successful
- No way to measure if requirements are met

<!-- Lines 145-155 -->

| Nice to Have | Bonus if achieved | Ship anyway |

### Mapping to Test Types
<!-- Lines 161-168 -->

| Criterion Type | Test Type |
|----------------|-----------|
| Functional | Acceptance tests, E2E tests |
| Performance | Load tests, benchmarks |
| Reliability | Chaos tests, failover tests |
| Business | Analytics, user research |

### Example Mapping
<!-- Lines 171-195 -->

```markdown
Criterion: SC-F01 "Create task in ≤ 3 clicks"

Test:
- Name: test_task_creation_click_count
- Type: E2E (Playwright)
- Steps:
  1. Navigate to dashboard
  2. Count clicks to create task
  3. Assert clicks ≤ 3
```

```markdown
Criterion: SC-P01 "Page load ≤ 2 seconds"

Test:
- Name: test_page_load_performance
- Type: Performance (Lighthouse)
- Steps:
  1. Load page in headless browser
  2. Measure First Contentful Paint
  3. Assert FCP ≤ 2000ms
```

### Automation
<!-- Lines 198-206 -->

Where possible, automate criteria verification:
- Run in CI pipeline
- Fail build if criteria not met
- Track trends over time
- Alert on regression
