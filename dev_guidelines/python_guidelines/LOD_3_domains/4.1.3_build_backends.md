## Core Concept
<!-- Lines 17-29 -->

A build backend is the tool that creates distributable packages from your source code. The `[build-system]` table in `pyproject.toml` specifies which backend to use.

**Build Process:**
1. Read project metadata from `pyproject.toml`
2. Discover source files to include
3. Generate artifacts (sdist, wheel)

## Backend Comparison
<!-- Lines 32-49 -->

| Backend | Best For | Pros | Cons |
|---------|----------|------|------|
| **hatchling** | Most projects | Fast, simple config, modern | Less mature ecosystem |
| **setuptools** | Complex builds | Mature, extensive features | Verbose config |
| **flit-core** | Pure Python | Ultra-minimal | Limited features |
| **poetry-core** | Poetry users | Poetry integration | Poetry-specific |
| **meson-python** | C extensions | Modern build system | Overkill for pure Python |

**Selection Flowchart:**
1. Pure Python, simple → `hatchling` or `flit-core`
2. C extensions → `setuptools` or `meson-python`
3. Using Poetry → `poetry-core`
4. Complex package discovery → `setuptools`
5. Monorepo → `hatchling` with workspaces

## Hatchling
<!-- Lines 52-91 -->

Hatchling is the modern default. Fast, minimal configuration, good defaults.

```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.hatch.build.targets.wheel]
packages = ["src/mypackage"]

[tool.hatch.build.targets.sdist]
include = ["src", "tests", "README.md"]
```

**Source Layout Support:**
```toml
# src layout (recommended)
[tool.hatch.build.targets.wheel]
packages = ["src/mypackage"]

# Flat layout
[tool.hatch.build.targets.wheel]
packages = ["mypackage"]
```

**Dynamic Version from VCS:**
```toml
[project]
dynamic = ["version"]

[tool.hatch.version]
source = "vcs"

[build-system]
requires = ["hatchling", "hatch-vcs"]
```

## Setuptools
<!-- Lines 94-135 -->

Setuptools is the original, most feature-complete backend.

```toml
[build-system]
requires = ["setuptools>=61", "wheel"]
build-backend = "setuptools.build_meta"

[tool.setuptools.packages.find]
where = ["src"]

[tool.setuptools.package-data]
mypackage = ["py.typed", "data/*.json"]
```

**When to Use Setuptools:**
- Building C/Cython extensions
- Complex package discovery needs
- Need `setup.py` compatibility
- Existing project with setuptools config

**C Extension Example:**
```toml
# Still need setup.py for extensions
[build-system]
requires = ["setuptools>=61", "wheel", "cython"]
build-backend = "setuptools.build_meta"
```

```python
# setup.py
from setuptools import Extension, setup

setup(
    ext_modules=[
        Extension("mypackage._speedups", ["src/mypackage/_speedups.c"])
    ]
)
```

## Artifacts
<!-- Lines 138-172 -->

Build backends produce two artifact types.

**Source Distribution (sdist):**
- Tarball of source code
- Includes `pyproject.toml`, source files
- Recipient builds from source

```bash
python -m build --sdist
# Creates: dist/mypackage-1.0.0.tar.gz
```

**Wheel:**
- Pre-built package
- No build step at install time
- Platform-specific for C extensions

```bash
python -m build --wheel
# Creates: dist/mypackage-1.0.0-py3-none-any.whl
```

**Wheel Naming:**
```
{name}-{version}-{python}-{abi}-{platform}.whl

mypackage-1.0.0-py3-none-any.whl     # Pure Python
mypackage-1.0.0-cp311-cp311-linux_x86_64.whl  # C extension
```

**Build Both:**
```bash
python -m build  # Creates both sdist and wheel
```
