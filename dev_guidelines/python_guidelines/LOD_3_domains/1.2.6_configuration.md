## Core Concept
<!-- Lines 33-66 -->

**Definition:** Configuration strategy defines how external settings (database URLs, API keys, feature flags) flow into your application and vary across environments.

**Key Points:**
- Separate configuration from code
- Support multiple environments (dev, staging, prod)
- Fail fast on missing required config
- Never commit secrets

**The 12-Factor Principle:**
> Store config in the environment

Configuration should be:
- External to the codebase
- Different per deployment
- Not in version control (especially secrets)

**Configuration Hierarchy:**
```
Command-line args    (highest priority)
    ↓
Environment variables
    ↓
Config files
    ↓
Default values      (lowest priority)
```

## When to Use
<!-- Lines 69-89 -->

**Design Config Strategy When:**
- Starting a new project
- Adding external service integrations
- Supporting multiple environments
- Managing feature flags
- Deploying to production

**Configuration Is Not:**
- Business logic (use code)
- Data (use database)
- Frequently changing values (use feature flags or database)

**Signs of Poor Config Strategy:**
- Secrets in git history
- Different behavior "on my machine"
- Hard to deploy to new environment
- Config scattered across codebase

## Configuration Sources
<!-- Lines 92-92 -->

### Environment Variables
<!-- Lines 95-110 -->

The primary configuration mechanism:

```python
import os

DATABASE_URL = os.environ["DATABASE_URL"]  # Required, fails if missing
DEBUG = os.environ.get("DEBUG", "false").lower() == "true"  # Optional with default
```

**Benefits:**
- Language-agnostic
- Easy to set in containers/CI
- Standard across platforms
- Twelve-factor compliant

### Config Files

For complex, structured configuration:

```yaml
# config.yaml
```

### Environment Detection
<!-- Lines 193-210 -->

```python
from enum import Enum
import os

class Environment(Enum):
    DEVELOPMENT = "development"
    TESTING = "testing"
    STAGING = "staging"
    PRODUCTION = "production"

def get_environment() -> Environment:
    env_str = os.environ.get("ENVIRONMENT", "development")
    return Environment(env_str)

ENV = get_environment()
```

### Environment-Specific Settings
<!-- Lines 213-225 -->

```python
# Derived settings based on environment
DEBUG = ENV == Environment.DEVELOPMENT
LOG_LEVEL = "DEBUG" if DEBUG else "INFO"

# Environment-specific values
if ENV == Environment.PRODUCTION:
    ALLOWED_HOSTS = ["myapp.com", "www.myapp.com"]
else:
    ALLOWED_HOSTS = ["*"]
```

### Config File Per Environment
<!-- Lines 228-247 -->

```
config/
├── base.yaml       # Shared settings

├── staging.yaml
```

```python
def load_config(env: Environment) -> dict:
    base = yaml.safe_load(Path("config/base.yaml").read_text())
    env_specific = yaml.safe_load(Path(f"config/{env.value}.yaml").read_text())
    return {**base, **env_specific}  # Merge, env-specific wins
```

## Python Implementation
<!-- Lines 250-250 -->

### Pydantic Settings
<!-- Lines 253-286 -->

The recommended approach:

```python
from pydantic_settings import BaseSettings
from pydantic import Field

class Settings(BaseSettings):
    """Application configuration."""

    # Required (no default = must be provided)
    database_url: str
    secret_key: str

    # Optional with defaults
    debug: bool = False
    log_level: str = "INFO"
    port: int = 8000

    # Validated
    max_connections: int = Field(default=10, ge=1, le=100)

    # Nested
    redis_host: str = "localhost"
    redis_port: int = 6379

    model_config = {
        "env_file": ".env",
        "env_file_encoding": "utf-8",
    }

settings = Settings()  # Loads from environment
```

### Validation
<!-- Lines 289-305 -->

Fail fast on invalid configuration:

```python
from pydantic import field_validator

class Settings(BaseSettings):
    database_url: str

    @field_validator("database_url")
    @classmethod
    def validate_database_url(cls, v: str) -> str:
        if not v.startswith(("postgresql://", "sqlite://")):
            raise ValueError("Invalid database URL scheme")
        return v
```

### Secrets Handling
<!-- Lines 308-321 -->

```python
from pydantic import SecretStr

class Settings(BaseSettings):
    # SecretStr hides value in logs/repr
    api_key: SecretStr
    database_password: SecretStr

# Usage
settings.api_key.get_secret_value()  # Explicit access
print(settings.api_key)  # Shows: SecretStr('**********')
```

### Singleton Pattern
<!-- Lines 324-337 -->

```python
from functools import lru_cache

@lru_cache
def get_settings() -> Settings:
    return Settings()

# Usage throughout app
from myapp.config import get_settings

settings = get_settings()
```
