## Mutable Default Arguments
<!-- Lines 16-65 -->

Mutable default arguments are shared across all calls to a function.

**The Problem:**
```python
def append_to(item, items=[]):
    items.append(item)
    return items

append_to(1)  # [1]
append_to(2)  # [1, 2] - Unexpected!
append_to(3)  # [1, 2, 3] - Same list!
```

**Why It Happens:**
Default arguments are evaluated once at function definition, not at each call. The same list object is reused.

**The Fix:**
```python
def append_to(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

append_to(1)  # [1]
append_to(2)  # [2] - New list each time
```

**Same Issue with Dicts and Sets:**
```python
# BAD
def add_key(key, data={}):
    data[key] = True
    return data

# GOOD
def add_key(key, data=None):
    if data is None:
        data = {}
    data[key] = True
    return data
```

## Late Binding Closures
<!-- Lines 68-118 -->

Closures capture variables by reference, not by value.

**The Problem:**
```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)

[f() for f in funcs]  # [2, 2, 2] - Not [0, 1, 2]!
```

**Why It Happens:**
The lambda captures the variable `i`, not its value. By the time lambdas are called, the loop has finished and `i` is 2.

**The Fix (Default Argument):**
```python
funcs = []
for i in range(3):
    funcs.append(lambda i=i: i)  # Capture value as default

[f() for f in funcs]  # [0, 1, 2]
```

**Alternative Fix (functools.partial):**
```python
from functools import partial

funcs = []
for i in range(3):
    funcs.append(partial(lambda x: x, i))

[f() for f in funcs]  # [0, 1, 2]
```

**Same Issue in Comprehensions:**
```python
# BAD
callbacks = [lambda: x for x in range(3)]
# All return 2

# GOOD
callbacks = [lambda x=x: x for x in range(3)]
# Return 0, 1, 2
```

## Name Shadowing
<!-- Lines 121-176 -->

Local variables shadow global or built-in names.

**Shadowing Built-ins:**
```python
# BAD: Shadows built-in
list = [1, 2, 3]
# list() no longer works!

id = 42
# id() broken!

# GOOD: Use different names
items = [1, 2, 3]
user_id = 42
```

**Commonly Shadowed Built-ins:**
- `list`, `dict`, `set`, `str`, `int`, `float`
- `id`, `type`, `input`, `open`, `file`
- `filter`, `map`, `sum`, `min`, `max`

**Shadowing Outer Scope:**
```python
x = 10

def outer():
    x = 20  # Different x

    def inner():
        x = 30  # Yet another x
        print(x)  # 30

    inner()
    print(x)  # 20

outer()
print(x)  # 10
```

**UnboundLocalError:**
```python
x = 10

def broken():
    print(x)  # Error! Python sees assignment below
    x = 20    # This makes x local to entire function

def fixed():
    global x
    print(x)  # 10
    x = 20
```

## Other Gotchas
<!-- Lines 179-243 -->

Additional Python behaviors that surprise developers.

**Integer Identity:**
```python
a = 256
b = 256
a is b  # True (cached small integers)

a = 257
b = 257
a is b  # False! (not cached)

# Always use == for value comparison
a == b  # True
```

**Chained Comparisons:**
```python
# This is valid Python!
1 < x < 10  # True if x between 1 and 10

# Equivalent to
1 < x and x < 10

# But watch out:
False == False in [False]  # True!
# Parsed as: (False == False) and (False in [False])
```

**String Interning:**
```python
a = "hello"
b = "hello"
a is b  # True (interned)

a = "hello world"
b = "hello world"
a is b  # May be False! (not interned)
```

**Tuple Assignment:**
```python
# Valid
a, b = 1, 2

# Gotcha: Trailing comma makes tuple
x = 1,    # x is (1,), not 1!
```

**Empty Collections are Falsy:**
```python
if []:      # False
if {}:      # False
if "":      # False
if 0:       # False
if None:    # False

# Check explicitly for None
if items is None:  # Not: if not items
    items = []
```
