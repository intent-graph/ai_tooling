## Documentation Hierarchy
<!-- Lines 18-52 -->

Different documentation serves different purposes and audiences.

**Documentation Stack:**
```
External Users
    ↓
[User Guides]      How to accomplish tasks
    ↓
[API Reference]    Complete interface docs
    ↓
[README]           Project overview
    ↓
[Docstrings]       Function/class contracts
    ↓
[Comments]         Implementation details
    ↓
Maintainers
```

**Audience Mapping:**
| Level | Audience | Question Answered |
|-------|----------|-------------------|
| Comments | Maintainers | Why is this code written this way? |
| Docstrings | Developers | How do I use this function? |
| README | Everyone | What is this project? |
| API Docs | Users | What's the complete interface? |
| Guides | Users | How do I accomplish X? |

## Code-Level Documentation
<!-- Lines 55-95 -->

Documentation closest to the code.

**Inline Comments:**
- Explain *why*, not *what*
- Reference external resources
- Mark TODOs and FIXMEs

```python
# Use binary search because data is pre-sorted and large (>10k items)
# See: https://en.wikipedia.org/wiki/Binary_search_algorithm
index = bisect.bisect_left(data, target)

# TODO(alice): Optimize for small inputs
# FIXME: Race condition when called concurrently
```

**Docstrings:**
- Document contracts (inputs, outputs, exceptions)
- Include examples when helpful
- Keep updated with code

```python
def fetch_user(user_id: int) -> User | None:
    """Fetch a user by ID.

    Args:
        user_id: The unique user identifier.

    Returns:
        User if found, None otherwise.

    Example:
        >>> user = fetch_user(123)
        >>> user.name
        'Alice'
    """
```

## External Documentation
<!-- Lines 144-184 -->

Documentation for external users.

**API Reference:**
- Generated from docstrings
- Complete interface coverage
- Examples for each endpoint

**Tutorials:**
- Step-by-step learning path
- Working code examples
- Progressive complexity

**How-To Guides:**
- Task-focused
- Practical solutions
- Common scenarios

**Diátaxis Framework:**
| Type | Orientation | Answers |
|------|-------------|---------|
| Tutorial | Learning | "Follow these steps to learn" |
| How-To | Tasks | "Do X to accomplish Y" |
| Reference | Information | "Here's how it works" |
| Explanation | Understanding | "Here's why it works" |

**Documentation Site Structure:**
```
docs/
├── index.md           # Overview
├── getting-started/   # Tutorials
│   ├── installation.md
│   └── quickstart.md
├── guides/            # How-tos
│   ├── authentication.md
│   └── deployment.md
├── reference/         # API docs
│   └── api.md
└── explanation/       # Deep dives
    └── architecture.md
```
