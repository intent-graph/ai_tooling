## Core Concept
<!-- Lines 17-33 -->

Dependency management balances two competing needs: flexibility for users who install your package, and reproducibility for developers who work on it.

**The Tension:**
- Libraries need flexible dependencies (compatible with many environments)
- Applications need pinned dependencies (reproducible builds)

**Solution:** Abstract dependencies in `pyproject.toml`, concrete in lock files.

## Abstract vs Concrete
<!-- Lines 36-67 -->

**Abstract Dependencies** (what you need):
```toml
[project]
dependencies = [
    "requests>=2.28",    # Any version >=2.28
    "pydantic>=2.0,<3",  # 2.x only
]
```

**Concrete Dependencies** (what you installed):
```
# uv.lock or requirements.lock
requests==2.31.0
certifi==2023.7.22
charset-normalizer==3.2.0
idna==3.4
urllib3==2.0.4
pydantic==2.5.2
pydantic-core==2.14.5
```

**When to Use Each:**
| Context | Use | Reason |
|---------|-----|--------|
| Library distribution | Abstract | Users need flexibility |
| Application deployment | Concrete | Reproducibility |
| Development setup | Lock file | Same env for all devs |
| CI/CD | Lock file | Deterministic builds |

## Version Specifiers
<!-- Lines 70-105 -->

PEP 440 defines version specifier syntax.

```toml
dependencies = [
    "pkg>=1.0",          # 1.0 or newer
    "pkg>=1.0,<2.0",     # 1.x only
    "pkg~=1.4.2",        # >=1.4.2, <1.5.0 (compatible release)
    "pkg==1.4.*",        # Any 1.4.x
    "pkg!=1.5.0",        # Anything except 1.5.0
]
```

**Operators:**
| Operator | Meaning |
|----------|---------|
| `>=` | Minimum version |
| `<` | Maximum (exclusive) |
| `~=` | Compatible release |
| `==` | Exact match (can use `*` wildcard) |
| `!=` | Exclude version |

**Best Practices:**
```toml
# Good: Minimum bound, tested upper bound
"requests>=2.28,<3.0"

# Avoid: Unbounded (may break with major version)
"requests"

# Avoid: Over-constrained
"requests==2.31.0"  # Only in lock files
```

## Optional Dependencies
<!-- Lines 108-140 -->

Optional dependencies enable features without forcing them on all users.

```toml
[project.optional-dependencies]
dev = [
    "pytest>=7.0",
    "ruff>=0.1",
    "mypy>=1.0",
]
postgres = [
    "psycopg[binary]>=3.0",
]
all = [
    "mypackage[postgres]",  # Reference other groups
]
```

**Installation:**
```bash
pip install mypackage[dev]      # Dev tools
pip install mypackage[postgres] # PostgreSQL support
pip install mypackage[dev,postgres]  # Multiple
```

**Common Groups:**
- `dev`: Development tools (testing, linting)
- `docs`: Documentation building
- `test`: Testing only (subset of dev)
- Database-specific: `postgres`, `mysql`, `sqlite`

## Lock Files
<!-- Lines 143-176 -->

Lock files capture the exact versions installed, including transitive dependencies.

**uv (recommended):**
```bash
uv lock              # Generate uv.lock
uv sync              # Install from lock
uv sync --frozen     # Fail if lock outdated
```

**pip-tools:**
```bash
pip-compile pyproject.toml -o requirements.lock
pip-sync requirements.lock
```

**Lock File Contents:**
```toml
# uv.lock (partial)
[[package]]
name = "requests"
version = "2.31.0"
dependencies = [
    { name = "certifi" },
    { name = "charset-normalizer" },
    { name = "idna" },
    { name = "urllib3" },
]
```

**Commit Strategy:**
- Applications: Always commit lock files
- Libraries: Commit lock files for development reproducibility
- CI: Use `--frozen` to catch drift
