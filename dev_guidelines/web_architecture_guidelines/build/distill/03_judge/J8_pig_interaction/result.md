### Judgments the L2 compresses

- **Accessibility level (VISUALIZE.4)**: the ledger states the page-level rule and that a level must be chosen; it does not name AA. AA contains every A criterion, so under the max rule it dominates A wherever it can be met; W3C rules out AAA as a site-wide requirement because some content cannot meet all AAA criteria. AA is therefore the most demanding level that can be required of every full page; AAA criteria are taken per page where the content allows. One jurisdiction's legal floor (US ADA Title II, WCAG 2.1 AA) agrees.
- **Push channel (REALTIME.1)**: J4 decided that correctness never depends on the channel. That removes the WebSocket-first argument's stake (buffered streams delay, they do not corrupt), so the simpler channel with built-in resume and cookie authentication wins for one-way push. The buffering risk is contained by the team's own proxy settings and a fallback for silent streams.
- **Fan-out without Redis (REALTIME.1, .3, .5)**: L437 adds Redis as soon as more than one process fans out. POSTGRES_FIRST (settled) keeps backing roles in Postgres until a measured limit and names the framework exception (L457). Each connection process holds one listening connection and re-reads the change table; Redis enters past the `NOTIFY` commit-lock limit (L127) or with a framework that requires it, and the change is committed to the table first in every case. Two costs are recorded: a full queue fails commits, so only changes with live subscribers notify and listeners run under the idle-in-transaction timeout; the commit-safe cursor's horizon lets one long transaction stall every push, monitored.
- **Required preconditions (EDIT)**: the sources differ on strictness (MAY, MUST honour, optional unless strong consistency). The strictest wins for every user-edited record, per-property last-writer-wins updates excepted (they carry no record version by design). Header clients get 412 and 428 as RFC 9110 defines them; HTML forms carry the version in a hidden field because a plain form cannot send `If-Match`, and a stale one is a conflict with current state, 409.
- **Automatic merge (EDIT)**: L675 lets the server merge disjoint fields. GUARD.5 (settled) rejects stale writes on discrete fields and admits per-property last-writer-wins only for toggles, status, assignment and ordering; automatic merge is kept for exactly those, sent alone without the record version.
- **Target version on every comment (COLLABORATE.1)**: L666 makes it conditional on edits invalidating comments and history existing. In the default every user-edited record is versioned (GUARD.5) and its history is written (ACT.4), so the cost is paid and the condition holds by default.
- **Deletion and revisions (COLLABORATE.2, .4)**: deleting a comment is a tombstone written by its deletion function: visible content cleared, replies kept as an explicit deviation from the cascade (L523), earlier revisions under the history's retention and access rules (moderators). Hard deletion for erasure conflicts with L525's archive copy; that tension and erasure itself belong to the deferred personal-data node.
- **Agent protocol (AGENT.1)**: agents are users in the default context, which means agents the team does not build; an MCP adapter over the same described core reaches them while holding no rule (RULES.4). The cost, one more surface, is bounded by the adapter's thinness, few purpose-specific tools, and the tool surface held to MD-02 like the HTTP description: one origin, a drift gate, additive evolution under the compatibility window.
- **Token binding (AGENT.3)**: L641's two positions win for high-value APIs and open ecosystems respectively; both exist inside one application, so binding follows the scope: key-bound tokens for consequential scopes, short narrow bearer tokens otherwise.
- **Server-held approval (AGENT.4)**: an approval dialog inside the agent host is a client hint (L650). The approval therefore lives in the application: a pending operation with exact parameters, approved by the owning user on the application's page, and a writer function that refuses an agent-originated irreversible effect without that approval (a rule decidable from stored rows and the actor, which GUARD.3 assigns to the writer function).
- **Nested quotas and scarce goods (AGENT.5)**: per user alone lets an agent starve its user; per agent alone needs a ceiling per integration; the nesting composes the three partitions L651 names. No quota stops one party running many accounts with an approved agent each, so on scarce-goods flows L652's denying position wins: a human step or no agents.
