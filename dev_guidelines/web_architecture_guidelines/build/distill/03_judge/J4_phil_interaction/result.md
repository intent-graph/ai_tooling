# Result: J4 web-app-philosophy INTERACTION judged

## L1 headline

All 12 INTERACTION nodes of `web-app-philosophy` are judged and decided on the settled allocation, now with the adversarial review applied (6 findings, all applied); none is undecided and no new question is raised. The interaction tier lets humans and agents work with the data through clients the team does not control, and decides nothing durable:
- server-rendered HTML that works for everyone, accessible from the start;
- pages correct on plain load, with push only as a hint and catch-up by a cursor no later commit can fall behind;
- comments as their own entities, never more visible than their target on any surface the application serves; reporting and operator roles see only what their grants allow, so their comment grants are restricted;
- agents as users through an adapter on the same core, with bounded scopes and tools, quotas and server-side audit; on flows that hand out scarce goods, a human completes the flow or agents are excluded;
- seven properties of the web environment designed for, from version skew (expand, migrate, contract, agent tools included) to hostile page script; no session token, bearer token or long-lived credential in a URL, short-lived signed file URLs excepted.

One clause awaits the maintainer by inheritance from authorization: who filters per-user comment visibility when several backends share the database. Until answered, each backend filters from a shared specification and runs shared denial tests. One evidence row is corrected: a sequence id is not a safe catch-up cursor (L594 against L682).
